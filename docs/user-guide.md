# BOOT ERP 사용자 안내

2026-11-06 / Asia/Seoul. 현재 구현된 UI/API를 기준으로 한 안내다. 신규 기능은 가상자료로 검증 중이며, 이 문서는 실제 Google 로그인·운영 배포·실자료 입력의 인수 완료를 뜻하지 않는다. 최신 실행 범위와 제한은 [진행상황](STATUS.md), [최종 증거](qa/f0-evidence-2026-11-06.md)를 따른다.

## 1. 로그인과 역할

관리자가 준비한 앱 주소에서 Google 계정으로 로그인한다. 사전 등록·이메일 소유 확인·활성화를 마친 계정만 사용할 수 있다. Google 계정 분실은 Google 복구 절차를 이용하고 ERP 연결/배정 문제는 담당자에게 문의한다. 현재 PC는 실제 Google OAuth 파일과 기존 인증 키가 없어 실제 로그인 검증을 완료하지 못했다.

| 역할 | 조회·처리 범위 |
|---|---|
| 연구원 | 현재 배정/인수한 업무와 신청·첨부·실적. 같은 과제의 공통 예산은 조회할 수 있으나 동료의 개별 자료·지급 실적은 비공개 |
| 과제책임자 | 담당 과제·비교과 전체 조회. 업무 작성·제출·검토·승인·지급/계정 변경은 하지 않음 |
| 담당자 | 전체 업무·배정·예산·신청 검토·실청구/지급 사실·업무 기준 관리. 일반 계정 우선 관리 |
| 관리자 | 허용된 대행과 전체 관리. 관리자 계정 관리·관리자 역할 부여/회수는 관리자만 수행 |

유휴 15분 또는 로그인 후 최대 8시간에 만료된다. 만료 2분 전 안내의 ‘계속 사용’은 유휴 시간을 연장하지만 최대 8시간을 늘리지 않는다. 계정당 동시 세션은 2개다. 우측 사용자 메뉴에서 전체 기기 로그아웃을 할 수 있다. Google/Gmail의 로그인까지 종료하는 기능은 아니다.

## 2. 화면 이동

상단은 업무 관리 / 현황·보고서 / 설정이다. 좌측은 업무·과제, 예산 관리, 지출 관리, 관리로 구성된다. 선택한 화면은 본문 위 탭으로 열리며 닫기 버튼으로 정리한다. 미저장 입력이 있으면 이동 안내를 확인하고 저장 여부를 판단한다. 경고를 지나간 입력이 자동 저장됐다고 간주하지 않는다.

작은 화면에서는 상단 ‘메뉴’를 눌러 좌측 메뉴를 펼친다. 넓은 표는 표 내부에서 좌우로 이동한다. 키보드는 본문 바로가기와 각 입력·버튼의 포커스를 이용할 수 있다.

## 3. 대시보드와 예산 숫자

사업연차·과제/비교과·기간을 선택하고 ‘조회’를 누른다. 현재예산·유효 신청 차감액·가용예산은 **조회 기준시점의 잔액**이며 기간 필터로 과거 잔액을 재구성하지 않는다.

`가용예산 = 현재예산 − 유효 신청 차감액`

실제 지급액은 지급일 기준 기간 지급 **총액(공제 포함)**이다. 공제와 실수령을 합친 값이며 환입은 별도 표시한다. 순집행은 기간 지급총액에서 기간 환입액을 뺀 값이다. 실제 지급액을 가용예산에서 다시 빼지 않는다. 특정 기간에 과거 지급의 환입만 있으면 기간 순집행이 음수일 수 있다.

연구원의 지급 실적은 본인 배정 업무 범위이며, 과제 공통 예산과 열람 범위가 다를 수 있다. 책임자는 담당 과제, 담당자/관리자는 허용된 전체 범위를 조회한다.

‘처리할 업무’는 담당자/관리자의 현재 신청·보완·지급 확인 대상이다. 과제·학년도 조건은 적용하지만 기간 조건과는 구분한다. 다른 역할의 담당자 전용 표시를 0건으로 해석하지 않는다. 최근 신청의 날짜는 원 초안을 작성한 날짜(KST)다. 내부 승인 배지는 지급 완료를 뜻하지 않는다.

‘현재 조회 내역 CSV’는 같은 조회범위·기준시점의 카드/표와 함께 대조한다. 조회 실패·권한 없음·미조회는 확인된 0과 구분된다.

## 4. 과제·업무·예산 배정

담당자는 과제·비교과를 등록하고 참여자를 배정한 다음 업무 담당 연구원을 지정한다. 업무 재배정 시 후임은 같은 업무의 과거 자료·첨부·이력을 승계하고 전임은 현재 접근권한을 잃는다. 원 작성자와 처리 이유는 보존된다.

‘배정·변경’에서 과제를 선택하면 항목별 최초예산·현재예산·신청 차감액·가용액과 분류 버전을 조회할 수 있다. 현재 최초 배정 입력은 담당자에게 제공된다. 연구원은 담당 과제의 항목 사이 예산변경을 신청할 수 있으나 과제 간 이동·총액 증감은 할 수 없다. 총액 증감은 담당자가 신청한다. 연구원·관리자 신청은 증감 합계가 0이어야 한다.

변경 신청에는 사유·변경 후 금액·근거 첨부가 필요하다. 담당자/관리자가 검토·확정하며 현재 신청 차감액을 침해하는 감액이나 낡은 버전의 처리는 거부될 수 있다. 원래 신청과 이전 첨부를 덮어쓰지 않는다.

## 5. 지출 신청과 첨부

신규 신청은 ‘지출 신청’ 또는 ‘지출 신청·검토’에서 작성한다. ‘초안·증빙’은 기존 공통 초안과 자료를 조회·관리하는 진입점이며, 제출·검토는 신청 화면에서 진행한다.

1. ‘새 초안 작성’에서 배정 업무와 지출 유형을 선택한다. 예산항목은 같은 과제의 항목 하나를 사용한다.
2. 제목·사용일·금액·목적·산출근거와 유형별 상세를 입력한다. 산출내역 여러 행을 쓰는 경우 수량×단가 합계는 신청금액과 같아야 한다. 다른 예산항목을 합쳐 차감하지 않는다.
3. 적용 기준을 선택하고 저장 사유를 적어 ‘초안·보완 저장’을 누른다. 불완전 초안은 저장할 수 있고 이때 예산은 차감되지 않는다.
4. ‘첨부·검토’에서 파일을 추가/교체하고 각 파일의 서류 역할을 지정해 저장한다. 같은 파일을 여러 역할로 연결할 수 있다. 파일을 교체하면 새 파일의 역할을 다시 확인한다.
5. 제출 준비가 끝나면 처리 사유를 적고 ‘신청 제출’을 누른다. 제출 시 기준·필수값·서류·잔액 검사를 통과해야 하며, 통과한 한 건을 한 번 차감한다.

단가/한도/기한 기준이 미설정·미확인 또는 초과이면 제출·승인이 제한된다. 연구인력지원비는 실제 지원 범위 설정 전까지 초안만 허용한다. 신청일에 적용한 기준과 제출본·첨부 버전은 보존한다. ‘미입력’은 제한 없음이나 적격 판정이 아니다.

허용 파일은 PDF, JPG/JPEG, PNG, HWP/HWPX, DOC/DOCX, XLS/XLSX다. ZIP은 지원하지 않는다. 파일당 5MiB, 현재 첨부 최대 10개·합계 20MiB 제한을 모두 적용한다. 확장자만 바꾼 파일은 거부될 수 있다. 파일은 현재 권한이 있는 사용자만 내려받을 수 있다.

## 6. 검토·보완·금액 정정

담당자는 ‘처리 시작’ 후 첨부·서류별 검토 의견을 남긴다. ‘보완 요청’은 기존 신청과 차감을 유지한다. 연구원은 같은 신청의 자료를 보완하고 ‘보완 제출’한다. 이후 필수 증빙은 내부 승인 전에 완비해야 한다.

보완 중 신청금액·유형·예산항목·단가 산출값을 직접 바꿔 기존 차감을 덮어쓸 수 없다. 금액 정정은 담당자가 ‘취소·복원 후 수정’으로 신청 이전 상태로 되돌린 뒤 수정·재신청한다. 재신청은 당시 가용액을 다시 검사한다.

연구원은 담당자 처리 전 본인 신청을 회수할 수 있다. 반려·취소·복원과 재신청은 이력으로 보존된다. 지급 기록이 있는 신청은 일반 취소·반려·회수·금액 수정으로 되돌려 예산을 다시 복원할 수 없다. 환입은 별도 절차를 이용한다.

‘제출본·이력’ 탭에서 당시 기준·금액·첨부와 처리 사유를 확인한다. 현재 초안을 수정해도 과거 제출본을 교체하지 않는다. 책임자에게는 처리 버튼이 제공되지 않는다.

## 7. 실청구·부분 지급·환입·마감

‘실청구·지급’에서는 승인된 신청과 현재 권한으로 열람 가능한 지급 사실을 조회한다. 담당자/관리자만 처리 사실을 기록한다.

- 대학 ERP 처리는 대학 ERP에서 수동으로 수행한 뒤 문서번호·처리일·근거·사유를 기록한다. 초기 구현은 신청 한 건과 외부 문서 한 건의 연결이다. 반려·재상신은 같은 연결의 추가 이력으로 남긴다. 외부 공식 승인 상태를 별도 필수 결재 단계로 만들지 않는다.
- 실제 지급은 실제 근거를 확인한 뒤 지급일·총액·공제·실수령을 수동 기록한다. 총액=공제+실수령이어야 하며 세율은 자동 계산하지 않는다. 부분 지급은 허용되지만 동일 신청의 누적 지급총액이 신청금액을 넘을 수 없다. 실청구 기록만으로 지급이 생성되지 않는다.
- 실제 환입은 원 지급을 선택하고 환입일·금액·근거·사유로 기록한다. 같은 원 지급의 누적 환입액이 지급총액을 넘을 수 없다.
- 예산복원은 환입 사실과 별개다. 원 사용연차·사용기간 내의 명시적 확인이 있을 때만 확인일을 적어 복원한다. 체크하지 않은 환입은 복원 보류로 남으며 나중에 같은 연차 조건을 충족하면 보류 환입의 복원을 확인할 수 있다. 연차를 넘는 환입은 사실만 보존하고 복원을 보류한다.
- 마감에는 내부 승인·신청금액 전액 지급·합계 일치·미복원 환입 없음·미해결 외부 반려 없음이 필요하다. 마감 중에는 추가 처리하지 않으며 담당자/관리자가 사유를 남기고 재개방할 수 있다.

환입으로 누적 지급총액을 0으로 지우지 않는다. 총 지급·환입·순집행을 구분하고 원거래를 삭제하지 않는다. 여기서 기록하는 행위는 송금·자동 상신·세금 신고를 실행하는 기능이 아니다.

## 8. 기준·계정 관리와 오류

‘단가·한도 기준’은 근거·기간·확인 상태·버전을 관리한다. 담당자가 설정하고 관리자가 대행한다. 책임자는 조회, 연구원은 적용 가능한 확인 완료 기준을 조회한다. 실제 수치를 모르면 가상 숫자로 운영 기준을 채우지 않는다.

계정 관리는 추가 본인 확인 뒤 사전 등록 → 이메일 수기 소유 확인 → 활성화 순서로 처리한다. 추가 확인은 5분 동안 유효하며 최초 인증 앱 등록도 Google 재로그인 후 정해진 시간 안에 해야 한다. 인증 키나 코드는 타인에게 보내거나 화면 캡처로 공유하지 않는다.

‘다른 변경이 있거나 현재 상태에서는 처리할 수 없음’은 낡은 화면 버전이나 선행 조건 변경일 수 있다. 새로고침 후 최신 상태·저장 결과를 먼저 확인하고 같은 실제 지급·환입을 별도 신규 건으로 무조건 다시 입력하지 않는다. 로그인 만료는 재로그인하고, 권한·배정 문제는 담당자에게 확인한다.

## 9. 운영·실자료·Notion 경계

현재 순서는 **구성/가상검수·운영준비 G1 → 실제 자료 입력·대조 G2 → 후속 Notion 연계**다. 좌측 Notion 항목은 추후 단계 안내이며 연결/전송 동작이 없다. 기존 Notion 원본은 읽기 전용이다.

실제 계정·이름·금액·증빙·키·원시 로그는 공개 저장소나 가상 검수 화면에 넣지 않는다. 백업·복구와 오류 대응은 운영 담당자가 [운영 안내](operations-runbook.md)를 따른다. 현재 운영 대상·보존/검역·복구 목표와 실제 인증 준비가 끝났다는 의미로 이 안내를 사용하지 않는다.
