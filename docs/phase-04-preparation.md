## 기존 확정 정책과 구현 경계

- 신청 즉시 차감, 보완 중 차감 유지, 처리 전 본인 회수, 복원 후 금액 수정·재신청을 유지한다. 승인·지급 시 중복 차감하지 않는다.
- 담당자 내부 승인과 실제 지급은 별도다. 외부 공식 승인 상태를 별도 관리하지 않는다.
- 연구원 간 개별 자료는 비공개이며 책임자는 담당 과제·비교과 조회 전용이다. 후임은 인수한 동일 업무의 과거 자료를 조회한다.
- 사업·연차·2026-03-01~2026-12-31 공통 사용기간·Notion 우선 분류는 확정됐다. 뒤늦은 등록·기간 밖 사용을 이번 답변으로 허용하지 않는다.
- 03의 예산변경 첨부와 04의 지출 증빙은 구분한다. 신청별 복수 파일·합계 제한·증빙 종류·제출본 이력은 04에서 구현·검수해야 한다.
- 실제 자료 DB 이관·Notion 수정·외부 자동 연동은 하지 않는다. 04 기능 구현도 이번 문서 작업에 포함하지 않는다.

## B. 유형별 기준 추천안

아래는 사용자가 정한 9개 유형에 대한 **미승인 업무 설계안**이다. 공식 필수서류·집행 가능 범위·세무 기준을 검증한 목록이 아니다. 기존 적용 자료와 대조한 뒤 채택·수정한다. B-01~B-09는 답변 번호이며 예산 분류 코드가 아니다.

### B 공통 추천

1. 아래 추가 입력은 해당 유형의 신청 시 입력한다. 실제 발생 전에는 예정 정보로 기록하고 실제 정보로 보완한 이력을 남긴다.
2. 신청 시에는 공통 정보와 금액 산출근거를 입력하고 보유 자료를 첨부한다. 별도의 파일을 모든 유형에 일괄 필수로 요구하지 않고, 신청 시 반드시 필요한 서류는 아래 표에서 제안한다.
3. 승인 전에는 지출 내용·산출금액·수행/납품 사실을 확인할 자료를 갖춘다. 거래 증빙은 거래 방식에 맞는 자료를 사용하며 예시 서류를 전부 중복 제출하게 하지 않는다.
4. 승인 전 증빙 때문에 ERP의 실제 지급을 먼저 요구하지 않는다. 지급 전 신청에는 청구서·계약·산출내역 등으로 확인하고, 지급 후 이체확인 등의 지급 사실은 후속 지급 단계에서 별도로 기록하는 방안을 추천한다. 승인값으로 지급을 추정하지 않는다.
5. 개인정보는 필요한 업무 정보만 비공개로 취급한다. 주민등록번호·계좌·신분증 사본을 이 추천안의 공통 필수항목으로 추가하지 않는다. 지급 단계에서 필요성이 확인된 자료는 별도로 설계한다.

### 단가·한도 설정 탭 구성 제안

**설정 탭 생성 요구는 확정**, 아래 화면 구성·운영 방식은 **추천안**이다. 이번에는 구현하지 않는다.

| 설정 항목 | 추천 내용 |
|---|---|
| 대상 | 지출 유형과 필요한 세부 구분(예: 학생/교수, 국내/국외, 개인/업체) |
| 계산 기준 | 1인·1일·1회·1개 등의 단위, 단가, 건별/기간별 한도. 숫자 초기값은 임의 생성하지 않음 |
| 기한 | 단가·한도와 별도 항목으로 확장 제안. 기준 사건·기간·영업일/달력일을 근거와 함께 관리 |
| 근거·적용 기간 | 자료명·버전·관련 항목·적용 시작/종료일·변경 사유 |
| 상태 | 확인 필요 / 확인 완료. 근거 확인 전에는 “제한 없음”으로 저장하지 않음 |
| 관리 권한 | 담당자가 등록·수정·확정, 관리자 대행. 책임자는 조회 전용, 연구원은 신청에 필요한 적용 기준 조회만 허용하는 안 |
| 변경 이력 | 버전과 변경자를 보존하고 신청에 적용한 기준을 기록. 새 값으로 이미 확정된 신청을 덮어쓰지 않음 |
| 미확인·초과 시 | 초안은 작성 가능, 기준 확인 전 최종 승인 차단을 추천. 초과 신청의 제출 차단/검토 허용 방식은 별도 선택 필요 |

적용 기준일을 신청일/사용일/계약일 중 무엇으로 정할지, 미확인·초과 시 어느 단계에서 차단할지는 관련 근거와 함께 결정한다. 이번 답변만으로 확정하지 않는다. 지출 유형별 값은 차후 설정으로 관리하며 코드에 임의 수치를 고정하지 않는다.
