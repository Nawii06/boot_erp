## A. 사용자 답변으로 확정된 사항

## 기존 확정 정책과 구현 경계

- 신청 즉시 차감, 보완 중 차감 유지, 처리 전 본인 회수, 복원 후 금액 수정·재신청을 유지한다. 승인·지급 시 중복 차감하지 않는다.
- 담당자 내부 승인과 실제 지급은 별도다. 외부 공식 승인 상태를 별도 관리하지 않는다.
- 연구원 간 개별 자료는 비공개이며 책임자는 담당 과제·비교과 조회 전용이다. 후임은 인수한 동일 업무의 과거 자료를 조회한다.
- 사업·연차·2026-03-01~2026-12-31 공통 사용기간·Notion 우선 분류는 확정됐다. 뒤늦은 등록·기간 밖 사용을 이번 답변으로 허용하지 않는다.
- 03의 예산변경 첨부와 04의 지출 증빙은 구분한다. 신청별 복수 파일·합계 제한·증빙 종류·제출본 이력은 04에서 구현·검수해야 한다.
- 실제 자료 DB 이관·Notion 수정·외부 자동 연동은 하지 않는다. 04 기능 구현도 이번 문서 작업에 포함하지 않는다.

## B. 유형별 기준 추천안

사용자가 B-01~B-09에 대해 “추천안 채택하고자 하니, 적용 전 기록만 남겨놓고 차후 결정”이라고 답했다. 아래 표는 **채택 의향이 있는 보류안**으로 보존하며 최종 채택·필수값 적용·구현 승인을 뜻하지 않는다. 공식 필수서류·집행 가능 범위·세무 기준을 검증한 목록도 아니다. B-01~B-09는 답변 번호이며 예산 분류 코드가 아니다.

| 후속 답변 항목 | 기록 상태 |
|---|---|
| B-01~B-09 세부 기준 | 채택 의향 기록, 최종 결정·적용 보류 |
| 연구인력지원비 실제 범위 | 확인 필요 유지 |
| 외부전문기술활용비 실제 범위 | 전문가 자문 및 업체 기술지원 등을 포함. 그 밖의 범위·조건은 임의 확대하지 않음 |
| 공통 제출 시점 | 추천 채택. 신청 시 기본정보·산출근거·보유자료, 승인 전 해당 필수 증빙 완비. 지급 전에는 청구·계약·산출 자료 등으로 확인 |
| 설정 탭 구성·관리 권한 | 추천 채택. 아래 확정 구성 참조 |
| 기준 미확인 시 | 초안 허용만 확정. 제출·최종 승인 허용/차단은 미결정 |

필수 증빙이 누락된 경우의 승인 차단(A-05)은 이미 확정됐다. 단가·한도 등의 기준 자체가 미확인인 경우의 승인 처리와 구분한다. 초안 저장은 지출 신청 제출이 아니므로 예산 차감을 발생시키지 않는다.

### B 공통 추천

1. 아래 추가 입력은 해당 유형의 신청 시 입력한다. 실제 발생 전에는 예정 정보로 기록하고 실제 정보로 보완한 이력을 남긴다.
2. 신청 시에는 공통 정보와 금액 산출근거를 입력하고 보유 자료를 첨부한다. 별도의 파일을 모든 유형에 일괄 필수로 요구하지 않고, 신청 시 반드시 필요한 서류는 아래 표에서 제안한다.
3. 승인 전에는 지출 내용·산출금액·수행/납품 사실을 확인할 자료를 갖춘다. 거래 증빙은 거래 방식에 맞는 자료를 사용하며 예시 서류를 전부 중복 제출하게 하지 않는다.
4. 승인 전 증빙 때문에 ERP의 실제 지급을 먼저 요구하지 않는다. 지급 전 신청에는 청구서·계약·산출내역 등으로 확인하고, 지급 후 이체확인 등의 지급 사실은 후속 지급 단계에서 별도로 기록하는 방안을 추천한다. 승인값으로 지급을 추정하지 않는다.
5. 개인정보는 필요한 업무 정보만 비공개로 취급한다. 주민등록번호·계좌·신분증 사본을 이 추천안의 공통 필수항목으로 추가하지 않는다. 지급 단계에서 필요성이 확인된 자료는 별도로 설계한다.

### 유형별 입력·증빙·제출 시점 제안

연구인력지원비의 실제 범위는 확인 필요로 유지한다. 외부전문기술활용비는 전문가 자문·업체 기술지원을 포함한다는 답변을 반영하되, 위 표의 세부 서류·조건은 다른 유형과 함께 보류한다. B 공통 추천 중 별도로 채택한 제출 시점 외의 상세 제안도 일괄 확정하지 않는다.

### 단가·한도 설정 탭 구성·관리 권한

사용자가 **설정 탭 구성·관리 권한 추천안을 채택**했다. 아래 구성과 권한·이력은 2안 범위로 구현했다. 실제 기준값·적용 기준일·처리 단계는 별도로 남긴다. 확인 완료 기준을 저장해도 제출·승인은 활성화되지 않는다.

| 설정 항목 | 확정 구성 및 미결정 경계 |
|---|---|
| 대상 | 지출 유형과 필요한 세부 구분(예: 학생/교수, 국내/국외, 개인/업체) |
| 계산 기준 | 1인·1일·1회·1개 등의 단위, 단가, 건별/기간별 한도. 숫자 초기값은 임의 생성하지 않음 |
| 기한 | 단가·한도와 별도 항목으로 구성. 기준 사건·기간·영업일/달력일을 근거와 함께 관리하되 실제 값은 확인 필요 |
| 근거·적용 기간 | 자료명·버전·관련 항목·적용 시작/종료일·변경 사유 |
| 상태 | 확인 필요 / 확인 완료. 근거 확인 전에는 “제한 없음”으로 저장하지 않음 |
| 관리 권한 | 담당자가 등록·수정·확정, 관리자 대행. 책임자는 조회 전용, 연구원은 신청에 필요한 적용 기준 조회만 허용 |
| 변경 이력 | 버전과 변경자를 보존하고 신청에 적용한 기준을 기록. 새 값으로 이미 확정된 신청을 덮어쓰지 않음 |
| 미확인·초과 시 | 기준 미확인 시 초안 작성 허용만 확정. 미확인 상태의 제출·최종 승인, 초과 신청의 제출 차단/검토 허용 방식은 미결정 |

적용 기준일을 신청일/사용일/계약일 중 무엇으로 정할지, 미확인·초과 시 어느 단계에서 차단할지는 관련 근거와 함께 결정한다. 이번 답변만으로 확정하지 않는다. 지출 유형별 값은 차후 설정으로 관리하며 코드에 임의 수치를 고정하지 않는다.

## 차후 결정용 기록 양식

지금 추가 답변을 요구하지 않는다. 사용자가 차후 결정을 진행할 때 아래 보류 항목만 작성한다. 확정된 A·제출 시점·설정 구성과 권한·초안 허용을 반복 질문하지 않는다.

```text
[차후 결정 — 현재는 적용 보류]
B-01~B-09 세부 입력·서류·조건: 최종 채택 / 수정 / 보류 유지
수정할 번호와 내용:
연구인력지원비 실제 범위: 확인 필요 / 확인한 내용:
외부전문기술활용비 추가 범위·조건(기존 자문·기술지원 외):
제출 시점 외 B 공통 세부 제안: 최종 채택 / 수정 / 보류 유지

[남은 기준]
기준 미확인 시 신청 제출: 허용 / 차단 / 확인 필요
기준 미확인 시 최종 승인: 허용 조건 / 차단 / 확인 필요
초과 금액 신청: 제출 차단 / 담당자 검토까지 허용 / 확인 필요
단가·기한 적용 기준일과 근거: 확인 필요 / 내용:
기타 조건부 기준: 확인 필요 / 확인된 내용:
```

위 양식의 선택지는 승인이나 허용으로 간주하지 않는다. 실제 개인정보·계좌·증빙 원문은 답변에 넣지 않는다.

2안 구현에서는 초안 저장 시 예산을 차감하지 않으며, B 필드·필수서류와 미결정 규칙을 적용하지 않는다. 기존 `budget-spend` API로도 제출·승인을 진행할 수 없다. 이는 현재 출시 범위 제한이며, 미확인 기준의 업무 처리 정책을 영구 차단으로 확정한 것이 아니다.

1. B 추천안을 채택 의향이 있는 보류안으로 보존하고 사용자의 차후 결정을 기다린다.
2. 개발자는 이미 현재 적용본으로 확인된 자료를 재사용해 유형별 조건·근거를 대조한다. 단가·한도·기한 값은 미확정 상태를 유지한다.
3. 차후 결정 시 유형별 기준과 남은 처리 동작·유형-예산항목 연결을 정리한다. 설정 구성·관리 권한과 초안 허용은 이미 받은 답변을 사용한다.
4. 보류 정책 확정 후 04 제출·검토·승인 화면과 03 금액 서비스를 연결하고 W-01/W-02 전체 흐름을 검수한다. 05 이후·실자료 이관·운영 배포로 자동 확대하지 않는다.
