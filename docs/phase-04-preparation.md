# 04단계 사전 준비표

점검일: 2026-10-18. **03 구현·검수 완료 → 04 준비 점검 완료·업무별 입력 대기 → 04 기능 미착수**다. [03 완료 재점검](history/2026-10-18-phase-03-close-review.md)과 [04 단계 계획](stages/04-pre-requests-evidence.md)을 함께 읽는다.

## 다시 결정하지 않아도 되는 사항

- 로그인·역할·연구원 간 개별 업무 비공개·책임자 조회 전용·동일 업무 인수인계는 확정됐다.
- 신청 즉시 차감, 처리 전 본인 회수, 보완 중 차감 유지, 복원 후 금액 수정·재신청, 지급 전 담당자·관리자의 승인 후 취소는 확정됐다.
- 담당자 승인으로 내부 승인 완료다. 외부 공식 승인 상태·문서번호를 필수 단계로 추가하지 않는다. 실제 지급은 별도다.
- 사업명·연차·공통 예산 사용기간·Notion 우선 분류·코드는 확정됐다. 실제 예산 DB 입력은 아직 하지 않았고 가상 구현의 차단 조건이 아니다.
- 예산변경 양식을 첨부로만 받는 정책은 확정됐다. 모든 지출 유형의 필수 증빙 목록이 확정된 것은 아니다.

## 준비 순서

| 순서 | 준비할 내용 | 현재 판단·담당 |
|---|---|---|
| 1 | 처음 사용할 지출 유형 목록 | 사용자/업무 담당자 확인. 회의비·출장비 등은 예시이며 현행 전체 목록이 아님 |
| 2 | 유형별 입력항목·필수서류·제출 시점·조건 | D-07 확인 필요. 예산 분류와 지출 유형을 구분해 개발자가 표로 대조 |
| 3 | 신청 1건의 예산항목 수와 선택 범위 | D-08 중 04에 필요한 부분만 사용자 확인 |
| 4 | 실제 사용하는 서식·지침의 버전·적용일·단가/기한 유무 | 기존 자료를 우선 재사용하고 업무 담당자가 최신성·적용 여부 확인 |
| 5 | 증빙의 파일 형식·용량·복수 파일·ZIP 처리 | 03 기술 한도와 구분해 사용자 필요량 확인 후 설계 |
| 6 | 가상 신청→차감→검토→보완→승인/복원 검수 자료 | 개발자가 준비 가능. 실제 개인정보·계정 추가·예산 이관 불필요 |

### 서류 제출 시점

서류마다 신청 시 필수인지, 담당자 승인 전 필수인지, 특정 조건에서만 필요한지 구분한다. 준비되지 않은 서류 때문에 신청을 불필요하게 막거나 필수서류 없이 승인하는 일을 방지하기 위한 기준이다. 서류 누락 시 차단할 단계는 아직 확정하지 않는다.

### 신청 범위

- **신청 1건에 예산항목 1개 또는 여러 개**: 현재 03 공통 서비스는 1개다. 초기 04도 1개로 시작하는 방안을 권고하지만 사용자 확정은 아니다. 여러 개라면 배분 합계·원자적 차감/복원 확장이 선행되어야 한다.
- **지출 신청의 항목 선택**: 본인 배정 업무와 같은 과제의 항목 전체인지, 담당자가 업무별로 지정한 항목만인지 확인한다. 현재 서비스는 배정 업무·같은 과제를 검사하며 업무별 예산항목 허용표는 없다. 연구원의 과제 전체 예산변경 권한과 개별 지출의 항목 선택 권한을 혼동하지 않는다.
- **업무 날짜**: 예산 사용기간은 확정이다. 사용 예정일/실제 사용일, 뒤늦은 등록·기간 밖 사용 등의 처리 기준이 필요하면 근거를 확인한다. 현재 공통 서비스의 제출일 기간 검사를 실제 사용일 검증 완료로 간주하지 않는다.

### 근거 자료와 파일

[자료 목록](08-sources.md)의 S-03~S-06 등 기존 제공 자료를 우선 대조한다. 목록은 사본의 식별 기록이며 최신 개정본·모든 지출 유형의 기준 확인 완료를 뜻하지 않는다. 변경된 자료만 추가로 확보하고 원문은 비공개 위치에서 읽는다. 확인되지 않은 단가·한도·기한을 임의 수치로 만들지 않는다.

03 예산변경 첨부는 파일당 최대 5MiB, PDF·이미지·한글·Office 계열을 지원한다. 04의 출발점으로 검토할 수 있으나 실제 스캔 용량·필요 파일 수를 확인해야 한다. 지출 증빙은 서류별 복수 파일과 이전 제출본 보존이 필요하다. ZIP 지원 여부는 별도 확인하며 ZIP 1개가 필수서류 전체 충족을 뜻하지 않는다. 운영 보존기간·검역·성능·백업 복구는 후속 운영 준비에서 결정한다.

## 답변 입력 양식

아래 추천안은 답변을 돕기 위한 **미승인 제안**이다. 사용자 답변 전에는 요구사항·결정기록의 확정값으로 옮기지 않는다. 실제 개인정보·증빙 내용 대신 업무 기준만 기입한다. 추천안이 맞으면 항목 번호와 함께 “추천안 채택”, 다르면 바꿀 부분만 적을 수 있다. 모르는 내용은 “확인 필요”로 남긴다.

### A. 기본 운영 추천안

| 번호 | 확인할 내용 | 추천안 또는 예시 | 이유·선택 시 영향 |
|---|---|---|---|
| A-01 | 처음 사용할 지출 유형 | **초기 후보:** 회의비·출장비·재료/소모품 구입비. 실제 사용하는 유형만 선택하고 명칭 수정 | 유형별로 필요한 입력과 서류가 달라 먼저 범위를 정함. 이 목록은 현행 기관 기준을 확인한 결과가 아님 |
| A-02 | 신청 한 건의 예산항목 수 | **추천:** 1개 | 기존 03 서비스를 활용하기 쉬움. 여러 항목을 한 번에 신청해야 한다면 배분·동시 차감·복원을 먼저 확장해야 함 |
| A-03 | 지출 시 선택 가능한 예산항목 | **추천:** 본인 배정 업무와 같은 과제의 항목 전체 | 현재 업무·과제 검사와 연결 가능. 업무별 지정 항목만 허용하려면 담당자의 항목 배정 기능 추가 필요. 어느 안도 타 연구원의 신청·증빙 열람을 허용하지 않음 |
| A-04 | 공통 입력항목 | **추천:** 과제·배정 업무·지출 유형·제목·사용 예정일 또는 실제 사용일·신청금액·목적/내용. 신청자는 로그인 정보로 자동 기록 | 날짜가 예정인지 실제인지 구분하고 실제 사용일 확정 시 이력을 보존. 원 단위 총액 입력, 단가·인원·수량은 유형별 추가 |
| A-05 | 증빙 제출 시점 | **추천:** 신청 시 공통 입력 필수. 이미 있는 근거는 첨부하고, 나중에 생기는 필수 증빙은 담당자 승인 전까지 보완. 필수 증빙 미비 시 최종 승인 차단 | 유형별로 신청 단계부터 필요한 서류가 있으면 별도 지정. 같은 신청 안에서 보완하며 예산은 최초 신청 시 차감 유지 |
| A-06 | 기존 서식 사용 | **추천:** 빈 서식은 파일 첨부로 사용하고 검색·검토에 필요한 공통 정보만 화면에 입력 | 서식 전체를 화면으로 복제하지 않고 초기 입력 부담을 줄임. 서식별 예외는 지정 가능 |
| A-07 | 파일 형식 | **추천:** PDF·JPG/JPEG·PNG·HWP/HWPX·DOC/DOCX·XLS/XLSX. ZIP은 초기 미지원 | 03 허용 형식을 출발점으로 사용. 서류별로 첨부하여 어떤 자료가 빠졌는지 확인하기 쉽게 함 |
| A-08 | 파일 크기·개수 | **추천:** 파일당 5MiB 이하, 신청당 최대 10개, 합계 20MiB 이하 | 개발 시작용 한도 제안이며 운영 성능 실측값이 아님. 실제 스캔 크기가 더 크면 수정. 04에 복수 파일·합계 제한 구현 필요 |
| A-09 | 단가·한도·기한 | **추천 처리:** 근거 확인 전 자동 적격 판정·임의 숫자 적용 안 함. 확인된 유형부터 적용 | 사용자가 자료명·버전·적용일을 확인해야 함. “확인 필요”는 제한 없음이나 승인 가능이라는 뜻이 아님 |
| A-10 | 기존 자료 최신성 | **추천 절차:** 기존 제공 자료를 우선 대조하고 변경본만 추가 제공 | “현재도 최신”인지는 사용자 확인 필요. 개발자가 임의로 최신본이라고 확정할 수 없음 |

위 A-05는 서류를 갖추는 시점에 대한 제안이며 사전 예산·사후 청구라는 두 개의 신청을 만들자는 뜻이 아니다. A-04의 날짜 입력만으로 기간 밖 사용이나 뒤늦은 신청을 허용하지 않는다. 해당 사례가 있으면 처리 기준을 별도로 적는다.

### B. 유형별 작성 예시

아래는 **가상 화면 설계 예시**다. 기관의 공식 필수 증빙·집행 가능 항목·법정 단가로 확인한 내용이 아니다. 실제 사용하는 서류명과 필요 시점으로 바꾼다.

| 예시 유형 | 유형별 추가 입력 후보 | 첨부자료 이름 후보 | 제출 시점 작성 예 |
|---|---|---|---|
| 회의비 | 회의명·일시·장소·목적·참석 인원 | 회의록·참석 확인 자료·영수증 | 이미 보유한 자료는 신청 시, 아직 없는 필수자료는 승인 전 |
| 출장비 | 출장자·기간·장소·목적·비용 구분 | 출장 관련 서식·결과보고·교통/숙박 증빙 | 신청 시 필요한 서식과 승인 전 보완 가능한 증빙을 구분 |
| 재료/소모품 구입비 | 품명·규격·수량·사용 목적 | 견적·거래내역·구매 증빙·수령 확인 자료 | 견적이 신청 필수인지 확인, 구매 후 발생 자료는 승인 전 |

특정 서류가 필요하지 않으면 제외한다. 예시에 없는 서류가 실제 필수라면 추가한다. 참석자·출장자 등의 실제 개인정보는 공개 답변 양식에 적지 않는다.

### D. 짧게 답변하는 예시

아래는 답변 방법을 보여주는 가상 예시이며 현재 사용자 답변으로 기록하지 않는다.

```text
A-01: 회의비와 출장비부터 시작.
A-02~A-08: 추천안 채택.
A-09: 확인 필요. 유형별 단가·기한은 담당자가 자료 확인 후 제공.
A-10: 기존 제공 자료의 현재 적용 여부 확인 필요.
B: 회의비·출장비 각각의 필수 서류와 제출 시점은 확인 후 작성.
```

이렇게 답하면 선택한 운영 제안만 확정할 수 있고, A-09/A-10 및 B의 미답변 내용은 확인 대기로 유지한다. “모두 추천안대로”라는 답변도 실제 규정·자료 최신성까지 검증됐다는 뜻으로 확대하지 않는다.

## 이후 작업

개발자가 답변과 기존 근거를 대조해 확정값·제안·미결정을 기록하고, 입력 필드와 03 서비스 확장 필요 여부·지출 증빙 권한을 설계한다. 자료 대조·설계·가상 검수 준비는 지금 가능하다. 실제 필수서류·차단 조건을 임의 확정하지 않는다. 04 구현 지시 후 기본 신청·증빙 화면과 관련 검수를 진행하며 05·06·실자료 이관으로 자동 확대하지 않는다.
