# ERP 완성 작업용 프롬프트

2026-11-05 / Asia/Seoul. [통합계획](completion-plan.md)의 P0~P9 실행 문구다. 문서 생성은 실행 완료가 아니다. 현재 실제 상태는 [STATUS](STATUS.md)를 따른다.

2026-11-06 갱신: 사용자가 선택한 [생성 이미지](design/erp-dashboard-concept-2026-11-06.png)와 같은 형태를 최종 UI 기준으로 적용한다. [이미지 기준 구현 명세](design/erp-ui-spec.md)를 통합 프롬프트와 P2~P7에서 필수로 읽는다. 이번 변경은 프롬프트 정정이며 UI 구현은 미수행이다.

최종 점검 후 실행 방식: [자동 진행/필수·최종 검사 규약](execution-checks.md)과 [진행표/최종 목록](execution-progress.md)을 사용한다. 통합 실행은 단계별 즉시 필수만 통과하면 자동 계속하고, 구현 순서 완료 후 F0에서 나머지를 묶어 확인한 뒤 G1을 판정한다. 아래의 ‘검수’는 해당 규약에 따라 즉시/최종로 구분한다.

각 블록은 그대로 복사할 수 있다. 공통 규칙은 이 파일을 읽도록 각 블록에 포함했다. 처음에는 P0 또는 아래 구성완료 통합 프롬프트를 사용한다. P8/P9는 순서와 실제 입력/연계 범위가 갖춰진 뒤 사용한다.

## 공통 실행 규칙

- AGENTS.md, STATUS, 요구사항, 최신 결정기록, 통합계획과 해당 단계 문서를 읽고 기존 변경·완료 코드·검수 증거를 보존한다.
- `docs/execution-checks.md`의 확인 루프와 단계별 최소 통과 조건을 적용하고 `docs/execution-progress.md`의 단계 상태/검사 결과/증거/이월을 실행 결과로 갱신한다. 이 문서를 읽었다는 이유로 구현 단계를 완료 처리하지 않는다.
- 화면 작업은 `docs/design/erp-dashboard-concept-2026-11-06.png`를 직접 열어 보고 `docs/design/erp-ui-spec.md`에 따라 구현한다. 이미지와 다른 대시보드로 임의 재설계하지 않는다. 이미지를 배경으로 붙이는 대신 실제 컴포넌트·조회·업무 동작으로 재현한다.
- 이미지는 담당자용 가상 컨셉이다. 역할·조회 범위·확정 정책이 우선하며 이미지의 금액·날짜·개인/과제명·건수를 하드코딩하지 않는다. Notion 하단 항목은 P9 이전에는 외부 동작 없는 추후 안내다.
- 확정 정책은 다시 묻지 않는다. 새 외부 사실/업무 미결정만 해당 단계에서 모아 질문한다. 미결정과 무관한 구현·검증은 계속하고, 답변 부재로 정책을 확정하지 않는다.
- BC/EX 최신 정책을 우선한다. 초안 미차감·제출 차감·보완 유지·복귀 복원·재신청 재검사·승인/지급 재차감 금지, 책임자 조회 전용과 연구원 격리를 유지한다.
- 미구현 기능을 버튼·더미 통계·성공 메시지로 완료처럼 보이게 하지 않는다. 동작하는 단계만 노출한다.
- 실제 자료·키·파일명·로그 등 민감값을 공개 저장소/대화/테스트 결과에 복사하지 않는다. Notion 원본 변경과 대학 ERP 자동 조작·상신·자동 지급은 하지 않는다.
- 해당 변경의 타입/핵심 기능·권한·금액·중복·동시성·파일/자료 보존·기본 UI는 즉시 검사한다. 매 단계 같은 전체 회귀·모든 화면/역할/뷰포트 행렬·세부 이미지 대조는 반복하지 않고 F0 목록에 이월한다. 핵심 실패/미결정은 이월로 숨기지 않는다.
- 현재 Windows는 `scripts/app.cmd`를 사용하며 DB·실제 로그인 검수는 비공개 설정 준비 후 수행한다. 명령별 실제 종료코드·결과를 확인하고 운영 DB에 개발 seed나 테스트 초기화를 실행하지 않는다. 유효한 통과 증거는 재사용하고 관련 변경이 생긴 검사만 재실행한다.
- 단계가 진행될 때 진행표와 STATUS·CHANGELOG·해당 history에 범위/즉시 결과/이월/차단을 간결하게 기록한다. 전체 문서의 중복 표현 정리는 F0로 모은다. 실제 결과/미실행·진입 조건·반영 SHA(실제 반영 시)를 남기며 문서만 바꾸면 문서 검증으로 보고한다.
- 통합 실행에서 ‘Pn만 수행’은 해당 단계 변경 범위이며 종료 지시가 아니다. 즉시 필수 통과·다음 선행조건 충족 시 사용자에게 매 단계 승인을 다시 묻지 않고 계속한다. 단일 Pn 요청은 그 단계 검사/기록 뒤 종료한다.
- 구현 완료/즉시 필수 통과(`step_passed`)와 최종 검증 완료(`verified`)를 구분한다. `failed/not_run/stale` 필수 결과를 성공으로 바꾸지 않는다. P0~P7 구현 뒤 F0 최종 필수를 처리한 다음 G1을 판정하고 P8/P9로 자동 확대하지 않는다.

