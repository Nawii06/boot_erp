# 04 제한 구현 사용 안내

기준일: 2026-10-20. 사용자 2안 선택에 따라 **공통 초안·비공개 첨부·단가/한도/기한 기준 관리**를 먼저 제공한다. 04 전체 완료는 아니며, 신청 제출·처리 시작·검토·승인은 아직 사용할 수 없다. 초안 저장은 예산을 차감하지 않는다.

## 1. 접속과 초안 작성

1. `http://localhost:3000`에 로그인하고 **지출 초안·증빙 → 초안 관리**로 이동한다.
2. 배정 업무와 9종 중 지출 유형을 선택한다. 과제는 배정 업무에 따라 결정된다.
3. 제목·예정/실제 사용일·금액·목적·산출근거를 아는 만큼 입력한다. 초안에서는 미입력을 허용한다. 금액을 입력할 때는 쉼표 없는 0 이상의 원 단위 정수를 쓴다.
4. 예산항목은 해당 과제의 항목 하나를 선택하거나 미선택으로 둔다. 항목·예산이 비어 있다면 기존 과제·업무 배정과 03 예산배정을 먼저 확인한다. 실자료를 자동으로 채우지 않는다.
5. 저장 사유를 입력하고 **초안 저장**을 누른다. 다시 열어 수정할 수 있고 이전 내용·작성자·사유는 수정 이력으로 남는다.

연구원은 현재 본인 배정 업무의 자료만 볼 수 있다. 같은 과제의 동료 초안·파일은 보이지 않는다. 책임자는 담당 과제·비교과 전체 조회만 가능하다. 담당자·관리자는 관리할 수 있고 실제 행위자를 기록한다. 업무를 재배정하면 후임은 이전 초안·파일·이력을 이어서 확인하며 전임의 접근은 해제된다.

다른 사용자가 먼저 수정했거나 같은 화면을 두 곳에서 저장했다면 버전 충돌이 발생할 수 있다. 최신 초안을 다시 열어 변경 내용을 확인한 후 저장한다. 같은 요청의 재전송은 중복 이력을 만들지 않는다.

## 2. 비공개 첨부와 교체

1. 저장한 초안의 **비공개 첨부**에서 설명·파일·사유를 입력한다.
2. 새 파일은 **새 첨부 추가**, 기존 파일 교체는 대상 파일을 선택해 **첨부 저장**한다.
3. 현재 파일과 **이전 첨부 포함 전체 이력**의 파일명을 눌러 내려받는다. 내려받을 때마다 현재 로그인·업무 권한을 검사한다.

허용 형식은 PDF·JPG/JPEG·PNG·HWP/HWPX·DOC/DOCX·XLS/XLSX다. ZIP은 거부한다. 파일당 5MiB, 현재 파일 최대 10개·합계 20MiB다. 교체 전 파일은 삭제하지 않으며 현재 파일 한도와 별도로 이력에 보관한다. 자료 설명은 업무상 메모이며 유형별 필수서류 충족 여부를 자동으로 판정하지 않는다.

파일은 공개 URL로 배포하지 않는다. 확장자·서명 및 일부 Office 컨테이너 구조를 검사하지만 악성코드 검역·문서 내용의 진위 검증까지 수행하지 않는다. 이력 포함 전체 저장량·보존/폐기·운영 검역은 운영 전 별도 검수 대상이다.

## 3. 단가·한도 설정

담당자·관리자는 **단가·한도 설정**에서 유형·세부 구분별 기준을 등록한다. 책임자는 조회 전용이며 연구원에게는 최신 버전이 확인 완료인 기준만 제공한다.

1. 자료가 아직 확인되지 않았다면 **확인 필요**로 저장한다. 빈 금액은 제한 없음 또는 0원으로 해석하지 않는다.
2. 확인한 단가·건별/기간별 한도·기한을 입력한다. 단가는 계산 단위, 기간별 한도는 집계 기간, 기한은 기준 사건과 달력일/영업일 구분을 함께 입력한다.
3. **확인 완료**로 기록하려면 근거 자료명·자료 버전·항목·적용 시작일과 하나 이상의 수치 기준이 필요하다. 변경 사유를 함께 입력한다.
4. 수정은 새 버전으로 저장하며 이전 기준을 덮어쓰지 않는다. 초안에서 **참고 기준 버전**을 선택하면 해당 버전 연결을 보존한다.

확인 완료 표시는 입력 담당자가 근거를 확인했다는 기록이다. 시스템이 기관 규정의 적법성을 검증했다는 뜻이 아니다. 현재는 참고 기준을 저장하는 범위이며 자동 계산·초과 판정·기한 판정·제출 활성화를 하지 않는다. B-01~B-09 세부 기준을 승인한 것으로 처리하지 않는다.

## 4. 남은 순서

1. 차후 결정 시 [04 준비표](phase-04-preparation.md)의 B 세부 필드·필수서류, 연구인력 범위를 확정한다.
2. 기준 미확인 시 제출·승인, 적용 기준일·초과 처리 규칙을 결정하고 확인한 실제 수치는 비공개 환경에서 입력한다.
3. 04 제출·검토·승인 화면을 03 금액 서비스에 연결해 제출 차감·보완 유지·복귀 복원과 파일 제출본을 검수한다.
4. W-01/W-02 등 04 전체 완료 조건을 충족한 뒤 다음 단계를 검토한다.

기존 `budget-spend` API도 현재 비활성화되어 직접 호출로 제출·승인을 우회할 수 없다. 이는 단계별 기능 개방 제한이며 미확인 기준의 최종 업무 정책을 임의 확정한 것이 아니다. Notion·외부 ERP 자동 연동, 실자료 이관, 05 이후 구현·운영 배포는 진행하지 않았다.

## 개발자 실행·검수

새 PC는 [개발 기반](foundation.md)과 [02 로그인 준비](phase-02-guide.md)를 먼저 따른다. 기존 PC는 아래 추가 마이그레이션을 적용한다. 실제 자료용 seed는 실행하지 않는다.

```powershell
.\scripts\app.cmd run local -- migrate
.\scripts\app.cmd run local -- migrate:test
.\scripts\app.cmd run typecheck
.\scripts\app.cmd test
.\scripts\app.cmd run local -- test:db
.\scripts\app.cmd run build
# test:ui는 localhost:3000이 비어 있어야 하며 격리 시험 스키마만 사용
.\scripts\app.cmd run local -- test:ui
.\scripts\app.cmd run local -- start --port 3000
# 서버 실행 중 별도 터미널
.\scripts\app.cmd run test:http
.\scripts\app.cmd run check:docs
```

실제 Google JSON·암호화 키·DB 접속정보는 기존 비공개 설정을 사용한다. 앱 실행 시 기존 `BOOT_ERP_GOOGLE_OAUTH_FILE` 환경변수도 유지한다. [검수 결과·실패/수정 기록](history/2026-10-20-phase-04-limited.md)을 참조한다.
