## 4. 실패와 증거 재사용

- 가상 입력 검사 최초 `npm exec -- node`는 오프라인 캐시 조회로 실패했고 샌드박스 직접 테스트는 자식 프로세스 EPERM으로 실패했다. 지정 Node의 승인 실행에서 13건 통과한 결과와 분리한다.
- 새 schema 카탈로그 검증 첫 두 실행은 PostgreSQL `name[]` 반환과 `pg_get_indexdef`의 정렬정보 반환 방식에 대한 테스트 코드 오류로 실패했다. text[] 및 indoption으로 보정 후 15건 통과했다. 이를 SQL 업무 결함이나 통과 이력으로 바꾸어 적지 않는다.
- 백업 첫 왕복은 기존 폴더 ACL 재설정 권한 문제로 9/10이었다. marked 폴더의 기존 보호상태를 확인하는 방식으로 수정한 후 10/10을 통과했다. 시스템 권한을 완화하지 않았다.
- 현재 루트와 담당자가 감사 이벤트의 시각을 transaction 시작시각 대신 잠금 후 삽입시각으로 보정 중이다. 관련 신청/지급/대시보드의 최신 이력 순서 검사는 보정 전 결과만으로 최종 통과시키지 않는다. 변경 후 영향을 받는 tests와 회귀 결과를 추가한다.
- 증거 재사용은 해당 코드·SQL/스키마·정책·의존성·환경의 무변경 범위를 먼저 확인한다. backup/import에 영향 없는 UI 수정 때문에 무관 도구 검사를 재반복하지 않는다. 반대로 서비스/스키마 변경이 관련된 결과는 `stale`로 표시하고 해당 검사만 다시 실행한다.
- 실OAuth 설정 부재는 가상 세션/HTTP 통과와 별개다. 로그인 우회·새 키로 기존 DB 덮어쓰기·가상 기준을 운영 초기값으로 두는 방식으로 차단을 해소하지 않는다.
