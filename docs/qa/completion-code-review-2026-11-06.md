위 보강은 확정된 공통 사용기간·신청일 기준·최신 검토의견을 보존하는 수정이다. 단가·세율·새 기관 규칙이나 실제 운영 기준값을 추가하지 않았다. 기본 마이그레이션과 기존 원자료는 덮어쓰지 않았다.

### R1 재현의 정확한 범위

새 고유 `foundation_test_<32hex>` 스키마의 probe 테이블에서 A가 먼저 BEGIN하고, B가 프로젝트 형태의 advisory lock을 잡도록 했다. A를 해당 잠금에 대기시킨 뒤 B의 accepted 기록·commit, A의 missing 기록·commit 순으로 진행했다.

- 실제 마지막 기록은 missing이다.
- 기본 CURRENT_TIMESTAMP 정렬은 accepted를 선택했다.
- 명시적 clock_timestamp 기록은 missing을 선택했다.

이는 현행 정렬에 사용하는 시각의 역전을 실제 PostgreSQL에서 증명한 것이다. 전체 API의 권한 우회 공격을 수행한 것은 아니며, 엄격한 버전 검사가 막는 경합도 있다. 계정 권한 우회가 발견됐다고 확대해서 기록하지 않는다. 추가된 시각은 프로젝트 잠금 획득 후 실제 기록 경로에서 계산한다. 시스템 시계 자체의 역행까지 해결하는 영구 순번 모델을 구현한 것은 아니다.

## 3. 남은 설계·운영 경계

- policy.subtype은 현재 관리자가 구성하는 자유 문구의 버전 묶음이다. 제공자 구분 등 details와 동일하다고 문자열을 추정해 자동 매칭하지 않는다. 유형 내 세부 정책의 적합성은 현재 설정 근거와 담당자 검토가 필요하다. 기관이 세부 자격을 기계적으로 차단하도록 요구하면 구조화된 적용 조건을 별도 확정해야 한다.
- 요구된 첨부의 존재/버전/역할과 의견 해결은 검사하지만 파일의 실제 내용이 증빙으로 적합한지는 담당자의 검토 사실이다. 파일 검역·보존·운영 용량 조건은 별도 미확정 범위를 유지한다.
- 지급 상세의 SQL DATE 응답 표시 문제는 동일 감사에서 다른 담당자가 확인하고 지급/실청구/환입/복원 날짜 응답에 ::text 보강한 코드를 확인했다. 그 경로의 실행 검수 증거는 별도 담당자의 F0 기록을 따른다.
- 현재 로컬 가상 환경 검수와 운영 대상·Google OAuth/기존 키·RPO/RTO 검수는 구분한다. 운영 대상이 미정이고 실제 인증·운영 복구 증거가 없으면 G1 전체 완료로 확정하지 않는다.
