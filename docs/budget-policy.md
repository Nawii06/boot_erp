# 예산 신청·변경·분류 정책

기준일: 2026-10-18. 사용자의 D-02/D-03/D-07 답변에 따른 확정 정책과 설계 해석이다. [결정기록](07-decisions.md)의 BC-01~BC-06을 따른다. 이번에는 문서·분류코드를 구성했으며 03 기능·DB 반영은 미수행이다.

## 신청 즉시 차감 — D-02

- 기본 예산에서 지출 신청 금액만큼 사용 가능 잔액을 즉시 차감한다. 내부검토 완료까지 차감을 미루지 않는다.
- 다음 신청은 이미 차감된 잔액 범위에서만 가능하다. 잔액 부족이면 신청과 차감 모두 실패해야 한다.
- 사전 예산·사후 청구의 별도 절차를 두지 않는다. 작성 중 초안은 신청 전이며 차감하지 않는다.
- 신청 건이 신청 이전 단계로 돌아가면 해당 신청의 차감을 취소하여 잔액을 복원한다. 재신청은 그 시점 잔액을 다시 검사한다.
- 사용자 표현의 차감 “삭제”는 차감 효력 제거로 구현한다. 원 신청·취소 사건과 행위자·사유를 보존하며 원장을 물리 삭제하지 않는다.
- 기본 예산 자체를 매번 덮어쓰지 않는다. 현재예산과 신청별 유효 차감액을 분리하여 잔액을 계산한다.
- 이 차감은 지출 신청에 적용한다. 항목 간 예산변경 신청 자체를 지출로 계산하지 않는다.

가용액 = 현재예산 - 유효한 신청 차감액 합계. 신청 승인·실제 지급을 별도 기록하더라도 같은 금액을 다시 차감하지 않는다. 실제 지급 여부는 신청이나 담당자 승인만으로 추정하지 않는다.

가상 예: 예산 1,000만원 → 100만원 신청 성공 시 900만원 → 다음 950만원 신청은 거부 → 첫 신청을 신청 전으로 되돌리면 1,000만원 → 90만원 재신청 시 910만원. 동일 요청 재시도는 차감·복원 각각 한 번만 반영한다.

신청·잔액 검사·차감·감사는 같은 DB 트랜잭션으로 처리한다. 동시 요청, 오래된 버전, 중복 클릭에서도 잔액이 음수가 되지 않도록 한다. 기존 코드의 예약 용어는 마이그레이션 시 이 의미로 정리하며 별도 사전예약 업무를 유지하지 않는다.

## 연구원 예산변경 — D-03

| 항목 | 확정 기준 |
|---|---|
| 연구원 신청 범위 | 본인이 담당하는 과제 전체의 예산항목 |
| 과제 내 비목·세목 이동 | 허용. 변경행 합계 0, 같은 과제 여부 검사 |
| 과제 간 이동 | 연구원에게 불허 |
| 총예산 증액·감액 | 연구원 불허. 담당자만 수행 |
| 내부 검토 | 담당자 |
| 변경 최종 확정 | 담당자, 관리자 대행 가능 |
| 필수 자료 | 변경 사유, 변경 전·후 금액, 첨부자료 |
| 감액 한계 | 기존 신청 차감·지급을 침해하는 감액 차단. 관련 건 정정·취소가 선행 |
| 외부 공식 승인 | 이 내부 ERP에서 관리하지 않음. 담당자 승인(허용된 관리자 대행 포함)을 시스템 승인 완료로 취급 |

총예산 증감의 수행 권한은 사용자의 “담당자만”을 적용하고, 관리자의 최종 확정 대행을 총액 증감 직접 수행 권한으로 확대하지 않는다. 과제책임자는 계속 조회 전용이다. 변경신청·다중 변경행·확정·감사를 원자적으로 처리하고 확정 이력은 덮어쓰지 않는다.

담당 과제 전체의 예산변경에 필요한 예산항목·금액 접근과 다른 연구원의 개별 업무·청구·증빙 열람은 구분한다. 타 연구원 자료 비공개 정책은 유지한다. 공통 잔액 표시 범위는 구현 시 최소 필요 정보로 제한한다.

외부 공식 승인 상태·문서번호를 변경 확정의 필수 조건으로 만들지 않는다. 이는 내부 시스템의 승인 정의이며 대학의 실제 승인·실제 지급을 수행했다는 증거로 기록하지 않는다.

## 분류·코드 — D-07

- 분류는 비목 → 세목 → 세세목의 3단계다. 과제와 비교과에 동일 분류체계를 사용한다.
- 사용자 지정 PDF의 “수정 후” 예산항목 좌·우 열을 비목·세목으로, 세부내용의 개별 금액 행을 세세목으로 매핑했다. 수정 전 항목을 현행 목록에 혼합하지 않는다.
- 여러 용도가 한 금액으로 묶인 원문 행은 하나의 세세목으로 보존한다. 산출 횟수·인원·과제 수는 설명으로 보존하며 같은 금액을 다시 곱하지 않는다.
- PDF의 산출 단가는 이 문서의 예산 근거이며 모든 업무에 적용할 보편적 법정 단가로 확정하지 않는다.
- 코드 형식은 비목 `B01`, 세목 `B01.01`, 세세목 `B01.01.001`이다. 각 단계 순번은 2/2/3자리로 부여한다. 원문에서 확인된 대학 공식 코드가 아니라 사용자 지시에 따라 구성한 ERP 내부 관리코드다.
- 최초 코드 발급 뒤에는 재사용하지 않는다. 이름·상하위 분류 변경은 내부 고유 ID, 코드, 버전·적용일·변경 전후·사유를 보존하고 관리한다. 코드 숫자에서 현재 부모 관계를 추정하지 않는다.
- 담당자·관리자가 분류를 추가·변경하고 승인한다. 외부 승인 절차를 추가하지 않는다. 사용된 분류는 삭제 대신 비활성화하며 과거 예산·신청의 당시 버전을 보존한다.
- 실제 금액·원문 매핑은 Git 제외된 로컬 참고 파일로만 작성했다. 공개 저장소에는 원문·실제 예산·개인정보를 넣지 않는다. DB seed에는 가상 값만 사용한다.

## 남은 세부사항과 다음 작업

확정된 정책을 다시 승인받지 않는다. 다음 사항은 아직 구체적으로 정해지지 않았으며 관련 기능 구현 전에 필요한 범위만 확인한다.

1. 제공 예산의 과제별·비교과별 배분액과 적용 사업연차/기간. 자료의 과제 수만으로 균등 배분하지 않는다. 공통 분류 사용이 동일 예산액 배정을 뜻하지 않는다.
2. 신청 전으로 되돌리는 상태 이름·수행 권한, 지급이 있는 건의 정정·환입 처리. 일반 보완 요청만으로 자동 복원한다고 추정하지 않는다.
3. 신청 후 금액 변경·추가/분할 신청의 세부 흐름. 변경 시에도 실제 유효 금액을 초과 차감하거나 잔액 없이 추가 신청을 허용하지 않는다.
4. 연구원 예산변경의 첨부는 필수로 확정됐다. 03 구현에서 비공개 첨부 저장·권한 검수를 포함해야 하며 전체 증빙 기능을 기다린다는 이유로 필수를 생략하지 않는다.
