# 자료 이관·시범운영·운영 관리

## 1. 저장 위치

코드·공개 설계·가상 테스트자료는 GitHub에 저장한다. 실제 업무자료는 운영 DB·비공개 증빙 저장소에, 내부 원문·기존자료 스냅샷은 기관 승인 비공개 보관소에 둔다. GitHub를 증빙 저장소나 운영 DB 백업 장소로 사용하지 않는다.

자료 원본의 보관소와 보존기간은 D-13/D-11에서 정한다. 법령상 보존기간을 이 문서에서 새로 단정하지 않으며 실제 적용 규정과 사업 종료 시점을 확인한다.

## 2. 이관 절차

1. 대상·기준시점·공식 처리상태 대조 기준을 정한다. 모든 과거 자료를 필수 이관하지 않는다.
2. 원본 Notion은 승인된 조회·내보내기만 사용하고 수정·상태정리·자동화 실행을 하지 않는다.
3. 비공개 스냅샷에 원본 페이지/행 ID, 원본값, 조회시각, 파일 참조를 보존한다.
4. 이관용 임시 영역에서 명칭·예산분류·프로젝트 관계를 매핑한다.
5. 원본 ID별 건수·배정금액·청구금액·상태·파일 수를 대조한다. 조회 누락·접근 불가·수식 미확인은 오류 목록으로 분리한다.
6. 시험 DB에 미리 실행(dry run)하고 담당자가 표본·총계를 확인한다.
7. 확정된 배치를 운영에 반영하고 원본 ID+배치 이력으로 중복을 방지한다.
8. 반영 후 불일치가 발견되면 해당 배치를 되돌리거나 정정한다. 이관 후 새 거래와 섞인 경우 무조건 삭제하지 않고 영향 분석 후 정정한다.

## 3. 상태·예산 이관 원칙

| 원본 정보 | 이관 원칙 |
|---|---|
| 승인(사용확정) | 원본 상태 보존, 실제 지급으로 단정하지 않음 |
| ERP등록 체크 | 기존 등록 표시로 보존, 공식 문서번호·지급 여부 별도 확인 |
| 수식/롤업 값 | 수식·원자료 대조 전에는 검증된 원장으로 사용하지 않음 |
| 현재 예산배정액 | 이미 변경 반영 여부 확인; 변경 이력을 다시 더하지 않음 |
| 항목명/세목 문자열 | 공식 분류코드와 수동 확인 가능한 매핑 |
| ZIP 또는 파일 링크 | 실제 파일 확보·해시·서류종류·검토상태 별도 확인 |
| 연락처 행 | 자동 계정 생성·권한 부여 금지 |

이관 기준시점의 확정 예산을 기초잔액으로 잡고 이전 변경을 참고 이력으로 둘지, 최초예산부터 모든 변경을 재구성할지 하나를 선택한다. 둘을 혼합해 이중 반영하지 않는다. 과거 지급·미지급 예약의 기초잔액도 실제 청구기록과 중복 집계하지 않는다.

## 4. 시범운영

- 산공과제 1건과 비교과 1건을 후보로 정하되 실제 대상은 담당자가 결정한다.
- 먼저 가상자료로 검수한다. 실제 자료 시험은 권한이 검증된 비공개 시험환경에서 한다.
- 공식 회계처리는 기존 경로에서 1회만 수행한다. 두 시스템 비교를 위해 실제 청구를 두 번 상신하지 않는다.
- 기존 관리자료는 비교 기준으로 읽되 Notion 수정 금지 지시를 유지한다.
- 수정이 필요한 업무 규칙은 결정기록에 남기고 고친 후 금액·권한 회귀검수를 수행한다.

## 5. 운영 전환

서버 소유자·운영 담당자, 접속 범위, HTTPS, 인증·계정 복구, 파일 용량·허용형식, 로그 보존·마스킹, 백업 대상·주기·복구목표, 장애 연락체계를 확정한다. 운영 비밀정보는 배포환경에 주입하고 저장소에 쓰지 않는다.

초기화·마이그레이션·배포·복구 명령은 10단계에서 실제 환경에 맞게 작성·시험한다. 운영에서 개발용 초기화/시드 명령이 실행되지 않도록 구분한다. 실데이터가 있는 DB에 단순 down migration을 자동 실행하지 않는다.

## 6. 백업과 복구

DB뿐 아니라 증빙 파일·파일 버전·필요 설정을 함께 백업한다. 암호화 키·비밀정보의 복구 경로도 별도로 마련한다. 운영 서버와 별개 저장 위치를 사용하고 정기 복원으로 검증한다. 파일과 DB의 기준시점이 달라 누락되는 경우를 점검한다.

복구 기록: 백업시점, 복원시점, 대상 버전, 건수·금액 대조, 파일 해시 표본, 계정·권한 확인, 소요시간, 손실 범위. RPO는 허용 자료 손실 시간, RTO는 목표 복구 시간이며 현재 미확정이다.

## 7. 향후 연동

이번에는 연동하지 않는다. 후속 요구가 생기면 원본 시스템·항목별 수정 권한·동기화 충돌·재시도·실패 대조·공개 범위를 새로 설계한다. 현재 Notion의 읽기 전용 조건은 새로운 명시적 지시 없이는 바꾸지 않는다.
