# 단계별 개발 로드맵

2026-11-06 실행 방식: 통합 P0~P7은 [자동 확인 규약](execution-checks.md)의 즉시 필수 통과 시 다음 선행조건을 확인해 계속한다. 무관한 전체 회귀·정밀 시각/전체 역할 행렬은 구현 후 F0에서 종합하며 G1 전에 최종 필수는 완료한다. 개별 단계의 종료 문구는 단일 단계 요청에 적용하고, 통합 실행의 상태는 [진행표](execution-progress.md)에 남긴다.

2026-11-05 실행 순서 갱신: [ERP 완성 통합계획](completion-plan.md)과 [P0~P9 작업 프롬프트](completion-prompts.md)를 우선 사용한다. 기존 00~10 번호는 유지한다. **구성·가상검수·운영/복구/입력도구 준비 → 실제 데이터 입력·대조 → Notion 실적 연계** 순서다. 09/10 준비 업무는 실자료 입력 전에, 실제 시범운영/최종 인수는 이후에 나눠 수행한다. 현재 기능 완료 범위는 아래와 같이 유지한다.

최신 실행: 2026-11-06 사용자 통합 지시로 P0~P7을 진행했다. **04~07 업무·이미지 UI 구현 및 가상 검수, 08/F0 로컬 통합 검수, 09/10 로컬 준비를 수행했으며 실제 인증/운영 조건 때문에 G1은 미완료다.** 현재 상태는 [진행표](execution-progress.md)와 [STATUS](STATUS.md), 사용은 [최신 사용자 안내](user-guide.md)를 따른다. 과거 2026-10-20의 04 제한 구현 증거는 이력으로 보존한다.

## 전체 순서

| 단계 | 목표·핵심 특이성 | 주요 검수 |
|---|---|---|
| [00. 개발환경·업무 정책 확정](stages/00-discovery.md) | 사용자의 로컬 PC와 실제 업무 조건을 확인하고 구현의 기준을 고정한다. | 문서·환경 확인 |
| [01. 개발 기반·DB·실행 환경](stages/01-foundation.md) | 새로운 개발자가 같은 명령으로 실행·검수할 수 있는 기반을 만든다. | 기반 실행·DB 검사, O-03 |
| [02. 계정·권한·과제·프로그램](stages/02-access-projects.md) | 확정된 로그인·계정·세션·열람 정책으로 실제 사용자와 업무 접근을 통제한다. | A-01~A-12 |
| [03. 예산배정·예산변경·금액 서비스](stages/03-budgets.md) | 프로젝트와 항목별 예산을 정확하게 계산하고 변경 근거를 추적한다. | B-01~B-05 |
| [04. 단일 지출 신청·증빙 기반](stages/04-pre-requests-evidence.md) | 확정된 신청·회수·차감 서비스를 연결하고 필요한 서류를 확인한다. | W-01, W-02, F-01~F-03 |
| [05. 신청 검토·보완·청구](stages/05-claims-review.md) | 같은 신청의 보완·금액 정정·제출본 이력을 연결한다. 사전/사후 별도 차감 없음 | W-03~W-05, F-03 |
| [06. 대학 ERP 실청구·지급·정산](stages/06-external-payments.md) | 담당자의 실제 대학 ERP 처리와 지급 결과를 추적 가능하게 기록한다. | E-01~E-07, B-06 |
| [07. 역할별 대시보드·집계·출력](stages/07-reports.md) | 업무 대기와 예산 현황을 정확한 같은 기준으로 조회·출력한다. | R-01~R-03 |
| [08. 통합·권한·금액 인수검수](stages/08-acceptance.md) | 실제 업무에 투입할 수 있는지 가상 데이터로 전체 흐름을 검증한다. | A/B/W/E/F/R 전체, O-03 |
| [09. 자료 이관 준비·제한 시범운영](stages/09-migration-pilot.md) | 원본을 보존하면서 필요한 기존 자료를 대조·이관하고 운영 적합성을 확인한다. | M-01~M-03 |
| [10. 운영 배포·백업복구·인수인계](stages/10-deployment-operations.md) | 승인된 환경에서 지속 운영·복구·인수인계가 가능한 상태로 전환한다. | O-01~O-03 |

각 단계 파일에는 선행조건, 개발 범위, 제외사항, 산출물, 완료 기준, 되돌림 방법, 복사해서 사용할 Codex 프롬프트가 있다. 위 순서가 기본이며 사용자 요청 없이 여러 단계를 한꺼번에 구현하지 않는다. 02 기능 구현·검수 및 실제 로그인·인증 앱 확인을 완료했다. D-02/D-03 및 D-07 분류 기준은 [예산 정책](budget-policy.md)으로 확정했다. 신청 전이·첨부 운영도 확정하고 Notion 배정자료를 읽기 전용 검토했다. 후속 답변으로 Notion 우선·공통 사용기간·등록 기준 분류를 확정했다. 03 구현·가상 검수를 완료했으며 다음은 04 단일 신청·증빙 준비다.

## 단계별 완료의 의미

| 구간 | 완료 시 사용 가능한 범위 |
|---|---|
| 00~02 | 실행 환경과 역할별 과제 접근 기반 |
| 03~05 | 예산 관리와 연구원 신청·청구·증빙, 담당자 검토 |
| 06~07 | 실청구·지급·정산 기록과 현황·출력 |
| 08 | 가상 데이터로 전체 흐름과 권한·금액 검수 |
| 09 | 원본 보존 이관과 제한 시범운영 |
| 10 | 승인 환경 배포와 백업 복구·운영 인수인계 |

06~07 구현 완료만으로 실운영을 시작하지 않는다. 업무 기능이 갖춰진 상태와 운영 검증이 끝난 상태를 구분한다. 새 실행계획의 G1은 구성·가상자료 인수·운영준비 완료, G2는 실제 자료 입력·대조 완료, G3는 후속 Notion 연계 완료다.

## 단계 공통 종료 절차

1. 해당 요구사항과 실제 동작을 대조한다.
2. 지정 검수를 실행하고 성공/실패/미실행을 구분한다.
3. 미해결 중대 결함과 다음 단계 영향 여부를 판단한다.
4. STATUS·CHANGELOG·작업기록·필요한 결정기록을 갱신한다.
5. diff와 공개 범위를 확인한 뒤 커밋·푸시하고 실제 결과를 남긴다.

## 일정 산정

단계별 기간은 아직 산정하지 않는다. 00단계에서 유지보수자 기술, 실제 사용자 수, 서식 수, 서버·인증 정책, 이관량을 확인한 뒤 예상 작업량을 산정한다. 이 목록은 일정 약속이 아니라 기능 의존성과 검수 순서다.

## 작업 방식

[VS Code·Codex 안내](05-codex-runbook.md)의 공통 절차를 따른다. 각 단계가 끝나면 사용자가 결과를 확인한 후 다음 단계 지시를 할 수 있다. 4종 역할·기존 Notion 읽기 전용은 유지한다. ERP 구성과 실자료 입력 중 외부 연계를 구현하지 않으며, Notion 실적 연계는 실자료 대조 후 별도 P9 범위로 정의한다.
