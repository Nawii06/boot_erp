# 자동 진행·단계별 필수 검사·최종 일괄 점검

2026-11-06 / Asia/Seoul. [작업 프롬프트](completion-prompts.md)의 실행 규약이다. 사용자가 단계 진행을 가능한 자동 확인하고, 해당 단계에 필수가 아닌 점검은 구현 순서가 끝난 뒤 묶어서 수행하도록 요청했다.

이 규약은 에이전트가 실제 도구/명령 결과를 확인하고 [진행표](execution-progress.md)를 갱신하는 절차다. 별도 백그라운드 실행기·스케줄러·진척 판정 프로그램이 설치된 것은 아니다. 문서 체크만으로 실제 기능 검증을 대체하지 않는다.

## 1. 진행 모드와 자동 계속

- **통합 P0~P7 모드:** 각 블록의 ‘Pn만 수행’은 그 작업의 변경 범위 제한이다. 단계 종료·다음 지시 대기가 아니다. 즉시 필수 조건을 통과하고 다음 작업의 선행조건이 충족되면 별도 확인 없이 자동 계속한다.
- **단일 Pn 모드:** 사용자가 한 단계만 지정하면 그 단계의 필수 검사·기록 후 종료한다. 전체 후속 구현까지 자동 확대하지 않는다.
- 필수 실패나 미확정 정책이 있으면 해당 의존 경로를 차단하고 먼저 원인을 수정한다. 가능한 독립 작업은 계속한다. 정책 답변·비공개 설정·실자료 범위·외부 변경 권한을 추정해서 통과시키지 않는다.
- 통합 흐름은 **구현 작업 P0~P7 → 최종 일괄 점검 F0 → G1 판정**이다. F0는 새 기능 개발 단계가 아닌 최종 검증 묶음이다. 구현 완료를 먼저 기록할 수 있으나 F0 통과 전에 ERP 전체 완료를 선언하지 않는다.
- 의존 단계 진입의 ‘선행 완료’는 관련 기능 구현과 즉시 필수 통과 증거를 뜻한다. 무관한 최종 이월까지 먼저 요구해 P3→P4→P7→F0 순환 대기를 만들지 않는다. P8/P9의 G1/G2와 실제 자료/외부 변경 선행조건은 최종 판정이므로 이 해석으로 낮추지 않는다.
- G1 뒤 P8, G2 뒤 P9는 각각 지정된 실제 입력/연계 범위가 있어야 실행한다. P0~P7 통합 실행이 이 경계까지 자동 승인한 것은 아니다.

## 2. 단계별 자동 확인 루프

1. 시작 시 진행표·최신 결정·코드/마이그레이션·기존 증거를 읽는다. 대상 기능이 이미 구현되고 증거가 유효하면 해당 결과를 재사용한다.
2. 현재 작업의 산출물과 아래 **즉시 필수** 항목만 먼저 선택한다. 기존 필수 정책·권한·금액 규칙은 변경하지 않는다.
3. 구현과 선택 검사를 실행한다. 각 명령별 시작/종료시각·명령·종료코드·검사 건수/결과·적용 범위를 기록한다. 여러 명령을 이어 실행했을 때 마지막 종료코드만으로 전부 통과라 판단하지 않는다.
4. 실패면 원인을 수정하고 영향받은 검사만 재실행한다. 코드 결함·샌드박스/환경 오류·설정 부재를 구분하고 동일 실패를 이유 없이 반복하지 않는다.
5. 즉시 필수가 전부 통과하면 진행표에 `step_passed`로 기록한다. 최종로 미룬 검사는 `deferred`로 따로 기록한다. 미실행/실패를 통과로 바꾸지 않는다.
6. 선행조건이 충족된 다음 작업을 선택해 계속한다. 의존 조건이 막히면 범위·필요 입력·가능한 독립 작업을 기록하고 이미 답변된 사항은 재질문하지 않는다.
7. P7 구현 후 F0 목록을 처리한다. 해당 결과로 `verified`와 G1 가능 여부를 판정하고 종료한다. 사용자의 상태 요청에는 현재 단계·필수 결과·이월/차단 항목만 간결하게 답하고 실행을 계속한다.

## 3. 즉시 필수와 최종 이월의 기준

| 구분 | 처리 시점 | 예 |
|---|---|---|
| 즉시 필수 | 변경이 다음 작업의 입력/근거가 되기 전 | 타입/실행 오류, migration 손실, 권한 우회, 금액·상태·감사·중복·동시성·파일 보안, 변경 화면 기본 동작 |
| 최종 필수 | P0~P7 구현 후 F0, G1 전에 완료 | 전체 회귀·전 역할/화면/뷰포트 종합검수, 완성 PNG 정밀 비교, 전체 E2E·성능·운영/복구·종합 문서/공개범위 점검 |
| 선택 점검 | F0에서 묶어 검토 후 처리/보류 판단 | 기능·접근성·이미지 주요 형태를 바꾸지 않는 미세 여백/아이콘 다듬기, 추가 예시·중복 설명 정리 |

최종로 미룬다는 것은 검사 삭제나 성공 간주가 아니다. 알려진 필수 결함, 보안/권한/금액/자료 손실 문제는 선택 항목으로 낮추지 않는다. 이미지 기준의 핵심 배치·가독성·필수 접근성은 최종 필수다. 선택 점검의 미처리는 사유를 남길 수 있지만 사용자 필수 요구를 선택으로 재분류할 수 없다.

| 작업 | 즉시 필수 검사/확인 | F0로 모아도 되는 항목 |

검수 ID는 [06 검수표](06-acceptance.md)를 가리킨다. 현재 구현에 대응하는 테스트가 없으면 의미 있는 검사를 추가한다. npm 스크립트는 파일 목록을 고정하고 있으므로 새 테스트가 실제 실행 목록에 포함됐는지도 확인한다. P3~P6의 핵심 검수가 존재하는데도 통합 검사라는 이름으로 전부 뒤로 미루지 않는다.

## 5. 기존 명령 재사용과 결과 확인

| 용도 | 명령 예 | 주의 |
|---|---|---|
| 설정 점검 | `.\scripts\app.cmd run doctor` | 파일 존재/Node 검사다. DB 접속/로그인 통과 증거가 아니며 종료 1의 누락/버전 사유를 구분 |
| 타입 | `.\scripts\app.cmd run typecheck` | TS 변경 시 즉시. 불필요한 매 단계 재반복은 생략 |
| 단위 | `.\scripts\app.cmd test` | 현재 테스트 목록과 새 테스트 포함 여부를 확인 |
| DB/핸들러 | `.\scripts\app.cmd run local -- test:db` | 격리 시험 DB/스키마에서 실행. 범위별 실행기는 실제 지원 명령을 확인하고 없는 옵션을 발명하지 않음 |
| 빌드 | `.\scripts\app.cmd run build` | F0에서 최종 실행. 생산 빌드에 의존하는 변경/실행을 검증해야 하면 즉시 |
| HTTP | `.\scripts\app.cmd run test:http` | 올바른 서버/DB가 실행 중인지 확인. 다른 포트는 실제 TEST_BASE_URL 지정. 단순 홈 200으로 DB 기능 통과 판단 금지 |
| UI | `.\scripts\app.cmd run local -- test:ui` | 격리 시험/빈 포트 준비. 기본 UI는 변경 시, 완전행렬·이미지 비교는 F0 |
| 문서 | `.\scripts\app.cmd run check:docs` / `git diff --check` | F0에서 종합 실행. 현재 수정의 정책 모순·민감정보는 즉시 확인 |

사용 가능한 명령·범위를 먼저 확인한다. 디렉터리/코드 파일·정책·DB 스키마·의존성/환경이 관련 없이 동일하면 기존 통과 증거를 재사용한다. 해당 증거 이후 관련 변경이 생겼다면 `stale`로 표시하고 영향 항목만 다시 검증한다. Git HEAD만 같아도 미커밋 diff가 다르면 같은 코드가 아니다.

자동 명령으로 증명할 수 없는 실제 로그인·화면 품질·사용자 정책 답변·기관 허용 환경은 도구 관찰/문서 근거/사용자 답변으로 확인한다. 사람 확인이 필요하면 해당 항목만 `blocked` 또는 `not_run`으로 기록하고 독립 작업을 계속한다. 원시 로그·스크린샷·실자료는 공개 진행표에 넣지 않고 정제 요약/가상자료 증거만 연결한다.

## 6. F0 최종 일괄 점검과 종료

P0~P7 구현 작업과 즉시 필수 검사가 끝나면 [진행표의 최종 목록](execution-progress.md)에 등록된 항목을 아래 순서로 처리한다.

1. 필수 이월의 유효성·선행조건 확인, 최종 코드 기준 타입/단위/DB/HTTP/빌드 회귀.
2. 가상자료 전체 업무 여정·네 역할 접근·동시성/중복·원장 대조와 파일/재배정/세션 회귀.
3. 기준 이미지 대비 1600×1000 및 1280×800/375×812, 전체 UI·주요 키보드·권한별 표시 검수와 필요한 시각 보정.
4. 합의한 성능/파일량/보존/검역, 별도 환경 DB+파일+필요 키 복원·롤백·RPO/RTO/운영/입력도구 검증.
5. 요구사항/명세/진행표/STATUS·CHANGELOG·history·사용/운영 안내, 링크·공백·공개 파일/로그/캡처의 민감정보 종합 점검.
6. 선택 점검은 묶어서 검토하고 범위 안의 필요한 수정만 한다. 필수 미충족을 ‘선택 보류’로 숨기지 않는다.

F0 중 수정이 생기면 영향받은 검사와 불변조건만 다시 실행하고, 이미 유효한 무관 검사를 처음부터 반복하지 않는다. 필수 항목의 `failed/not_run/blocked/stale`가 남으면 G1 미완료다. 모두 충족하면 단계 상태를 `verified`로 확정하고 G1 완료를 보고한다. 수정 코드·범위가 없다면 테스트만 반복하며 완료를 미루지 않는다.

최종 보고는 단계별 상태, 즉시 검사, 최종 일괄 결과, 선택 보류, 남은 사용자/외부 입력과 G1 판정을 요약한다. 실자료 P8·Notion P9는 시작하지 않는다.
