## 테스트 수준과 후속 검수

금액 서비스 단위검사, 실제 DB를 사용하는 권한·트랜잭션 통합검사, 브라우저 사용자 여정 검사를 구분한다. 동시성 검사는 단일 순차 요청만으로 대체하지 않는다. DB 테스트는 운영용 계정·데이터를 사용하지 않는다.

핵심 여정: 연구원 로그인 → 배정 업무 → 사전신청 → 담당자 보완 → 재제출 → 공식 사전품의 기록 → 사용 후 청구 → 담당자 검토 → 대학 ERP 수동 처리기록 → 부분 지급 → 지급완료 → 정산 → 책임자 조회.

## 완료·보류 기준

- 권한 우회, 금액 불일치, 이력 손실, 원본 변경, 복구 실패가 남으면 운영 전환하지 않는다.
- 소규모 실제 시범운영은 08단계 핵심 검수 통과 후 별도 비공개 환경에서 한다.
- 성능·파일 크기·동시 사용자 목표는 D-11에서 수치로 정한다. 임의 수치를 실측 결과로 제시하지 않는다.
- 사용자 인수확인은 업무 문구·필요 서류·처리 순서를 담당자가 실제 사례와 대조하여 기록한다.
