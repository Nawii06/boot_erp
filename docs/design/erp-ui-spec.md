# 생성 이미지 기준 ERP 화면 구현 명세

2026-11-06 / Asia/Seoul. 사용자가 생성된 이미지와 같은 형태가 되도록 작업 프롬프트 변경을 요청했다. 이 문서는 P2~P7에서 사용할 디자인·시각 검수 기준이며 이번에 UI가 구현됐다는 의미가 아니다.

## 1. 기준 이미지와 우선순위

- 필수 시각 기준: [완성 예상 대시보드 PNG](erp-dashboard-concept-2026-11-06.png).
- 이미지의 의도·생성 배경: [컨셉 설명](erp-dashboard-concept-2026-11-06.md).
- 실행: [작업 프롬프트](../completion-prompts.md), [통합계획](../completion-plan.md).
- 업무·권한·금액 정책은 최신 사용자 결정 및 BC/EX를 따른다. 이미지는 **담당자용 완성 예상 화면**으로, 날짜·과제·금액·건수는 가상 예시다.

새 디자인으로 재해석하지 말고 이미지의 정보 순서·메뉴 구획·색상 계열·밀도·정렬·대략적 비율을 재현한다. UI는 실제 HTML/CSS/컴포넌트와 동작하는 조회/업무 흐름으로 만든다. PNG를 화면 전체에 붙여 넣거나 클릭 영역만 겹쳐 구현하지 않는다. 이미지 밖의 과제/신청 상세도 같은 화면 틀·제목·폼·표 스타일을 적용한다.

## 2. 공통 화면 틀

| 구역 | 구현할 형태 |
|---|---|
| 최상단 흰 헤더 | 왼쪽 BOOT ERP와 부트캠프 사업관리, 오른쪽 현재 날짜·현재 사용자 역할·로그아웃. 날짜/역할은 실제 상태 사용 |
| 파란 상단 메뉴 | 업무 관리 / 현황·보고서 / 설정. 흰 글자, 활성 항목은 밝은 밑줄로 표시 |
| 흰 좌측 메뉴 | 데스크톱 약 220~240px, 선 아이콘·그룹명·얇은 구분선, 선택 항목은 연한 파란 배경과 남색 글자 |
| 작업 탭 | 본문 위에 대시보드 / 예산 현황 / 지출 신청 등 실제 연 화면, 활성 탭은 흰 배경·파란 테두리. X를 표시하면 닫기 동작과 미저장 안내도 구현 |
| 경로·제목 | 탭 아래 작은 업무 경로, 굵은 업무·예산 현황 제목. 다른 업무 화면도 같은 계층 사용 |
| 본문 | 좌측 메뉴를 제외한 남은 폭 사용. 기존 1100px 중앙 정렬 제한으로 이미지의 넓은 표 구조를 줄이지 않음 |
| 하단 안내 | 내부 승인·실청구·실제 지급을 구분한다는 안내 유지. 가상 검수 모드에만 컨셉/가상 데이터 표시 |

브랜드와 메뉴는 이미지처럼 간결하게 한다. 헤더의 종 아이콘은 실제 알림 기능이 있을 때만 기능으로 연결하며, 이 이미지를 근거로 새 알림 시스템을 별도 범위 없이 만들지 않는다. 기존 추가 본인 확인·전체 기기 로그아웃 등 보안 기능의 진입점은 사용자 메뉴/관리 영역 등에 보존한다.

## 3. 좌측 메뉴와 이동

완성 시 담당자용 메뉴는 아래 그룹 순서와 이름을 기준으로 한다. 상단 업무 관리는 업무/예산/지출, 현황·보고서는 조회/출력, 설정은 권한 있는 업무 기준/계정 화면으로 연결한다. 사이드바 메뉴와 상단 메뉴는 같은 경로/화면 상태를 공유하고 서로 다른 복제 화면으로 만들지 않는다.

| 그룹 | 항목 |
|---|---|
| 첫 항목 | 대시보드 |
| 업무·과제 | 내·전체 업무, 과제·비교과 |
| 예산 관리 | 예산 현황, 배정·변경 |
| 지출 관리 | 지출 신청, 검토·보완, 실청구·지급 |
| 관리 | 단가·한도 기준, 계정·권한 |
| 하단 미래 안내 | Notion 실적 연계 + 추후 단계 배지 |

업무 이름은 역할에 맞춰 내 업무/전체 업무로 표시할 수 있다. 다른 역할에 담당자 메뉴를 그대로 노출하지 않는다. 연구원은 동료 개별 자료·집계를 볼 수 없고 책임자는 조회 전용이다. 단가·한도 기준의 연구원/책임자 조회 권한은 기존 정책대로 보존한다. 계정 관리와 추가 본인 확인은 기존 역할·보안 정책을 따른다.

미구현 기능은 실행 가능한 버튼/성공한 현황처럼 표시하지 않는다. 단계 중 필요하면 해당 항목을 비활성 준비 상태로 표시하고 실제 제공 범위를 구분한다. Notion 하단 항목은 G2 이전에는 외부 링크나 전송 동작 없는 추후 안내로만 두며, 연결 완료·동기화 성공 표시를 하지 않는다.

## 4. 대시보드의 필수 배치

완성된 담당자용 대시보드에서는 아래 순서와 구획을 유지한다.

1. **검색 띠:** 사업연차 → 과제·비교과 → 기간 → 오른쪽 파란 조회 버튼. 선택 과제/업무 범위와 날짜 기준을 식별할 수 있게 한다.
2. **가로 4개 카드:** 현재예산 / 유효 신청 차감액 / 가용예산 / 실제 지급액. 아이콘 영역·작은 라벨·큰 금액을 배치하고 가용예산은 파란색으로 강조한다.
3. **중간 2열:** 왼쪽 약 2/3은 예산항목별 현황, 오른쪽 약 1/3은 처리할 업무. 패널 제목은 남색 띠와 흰 글씨로 통일한다.
4. **하단 전폭 표:** 최근 지출 신청, 오른쪽 지출 신청 버튼, 상태 배지와 각 행의 상세 버튼.

| 패널 | 표시 내용 |
|---|---|
| 예산항목별 현황 | 예산항목 / 현재예산 / 신청 차감액 / 가용예산 / 실제 지급액, 합계 행·원 단위 표시·내역 보기 |
| 처리할 업무 | 검토 대기 / 보완 확인 / 지급 확인의 실제 건수, 신청 검토 / 지급 내역 확인 바로가기 |
| 최근 지출 신청 | 신청번호 / 과제·비교과 / 제목 / 신청금액 / 상태 / 신청일 / 상세 보기 |

대시보드의 기간은 지표 정의 없이 모든 값에 같은 방식으로 적용하지 않는다. 현재예산/차감/가용액은 명시한 기준시점의 잔액, 기간 지급액은 확정한 지급일 등 날짜 기준의 실적으로 구분한다. 필터를 같은 조회 요청/집계 정의로 해석하고 카드·표·출력에서 의미가 다른 값은 라벨·기준시각으로 설명한다.

## 5. 시각 스타일

- 전체는 흰색과 연한 회청색 바탕, 상단은 선명한 파랑, 패널 제목은 남색이다. 가용 금액과 주된 이동/조회 동작은 파랑으로 강조한다.
- 구현용 시작 토큰 예: primary `#0B50C8`, panel `#203D68`, canvas `#F3F6FB`, border `#CFD8E5`, text `#182335`. 실제 대조 시 이미지에 맞춰 조정한다. 이미지의 픽셀을 엄밀히 추출한 색상값은 아니다.
- 한국어 시스템/고딕 글꼴, 짧은 그룹명, 줄 높이가 일정한 표, 작은 모서리 둥글기, 얇은 테두리를 사용한다. 거대한 카드·넓은 빈 공간·강한 그림자로 바꾸지 않는다.
- 표 제목/합계와 헤더는 명확히 구분한다. 금액은 오른쪽 정렬, 천 단위 쉼표, 단위 원, 명칭은 왼쪽 정렬한다. 숫자는 자릿수 비교가 쉽게 표시한다.
- 상태 배지는 글자와 색을 함께 사용한다. 검토 대기는 주황, 보완 요청은 파랑, 내부 승인은 초록 계열로 표현하되 실제 확정 상태 이름과 대응한다. 승인을 지급 완료처럼 표시하지 않는다.
- 아이콘은 기존 자산/간단한 SVG 등 일관된 선 아이콘을 사용한다. PNG의 아이콘을 자르거나 디자인 일치만을 위해 대규모 UI 라이브러리를 도입하지 않는다.

## 6. 데이터·기능 단계별 적용

| 시점 | 이미지 기준 적용 | 완료로 표시하면 안 되는 것 |
|---|---|---|
| P2 | 공통 틀·메뉴·필터/패널 구성과 현재 업무/예산/초안 기능을 적용, 미구현 데이터 영역은 준비/미조회 상태로 구분 | 가상 지급액·검토 건수를 하드코딩한 운영 대시보드 |
| P3~P5 | 같은 틀 안에서 신청·보완·검토·실청구·지급 상세와 실제 행동 연결 | 정책 미확정 제출/지급 경로의 임의 활성화 |
| P6 | 네 카드·두 중간 패널·최근 신청을 공통 서버 집계/필터·권한과 연결해 대시보드 완성 | 이미지의 숫자·날짜·신청 상태를 실제 값처럼 고정 |
| P7 | 화면 일치와 역할/반응형/동작/금액 검수 증거 확보 | 시각 일치만으로 전체 ERP/운영 G1 완료 선언 |
| P8~P9 | 실자료로 바뀌어도 화면 형태 유지, G2 후 별도 Notion 연계 정의에 따라 적용 | 컨셉에 Notion 글자가 있다는 이유로 선행 연계 수행 |

`가용예산 = 현재예산 - 유효 신청 차감액`을 유지한다. 실제 지급액은 지급 근거의 별도 사실이며 다시 빼지 않는다. 지급·환입의 상세 정의와 과거/기간 집계는 최신 정책을 적용한다. 데이터 없음은 확인된 0과 구분하고 서버 실패·권한 없음은 0으로 처리하지 않는다.

## 7. 화면 검수 기준

실행 시점은 [자동 확인 규약](../execution-checks.md)을 따른다. P2~P6에서는 변경 화면의 기본 동작·권한·가독성·대표 작은 화면/키보드를 즉시 확인하고, 아래 모든 화면/역할/뷰포트 행렬과 정밀 PNG 대조는 구현 순서가 끝난 F0에 모아 수행한다. 기본 오류·데이터 유출·입력 손실은 최종로 미루지 않는다. 최종 시각 기준 자체를 생략한 것은 아니다.

- 가상자료를 사용하는 격리된 인증 시험 환경에서 담당자용 화면을 기준 이미지와 나란히 비교한다. 원본은 약 1587×992px이며 대조 뷰포트는 1600×1000px을 기준으로 한다. 추가로 1280×800px과 모바일 375×812px에서 확인한다.
- 상단 2개 띠, 좌측 그룹 메뉴, 작업 탭·경로, 필터, 가로 카드 4개, 중간 2:1 패널, 하단 전폭 표의 구획과 순서가 맞는지 확인한다. 렌더링/글꼴 차이를 포함한 완전 픽셀 동일 여부로 판정하지 않는다.
- 가상 시험 데이터로 이미지의 합계 예시를 사용할 수 있으나 테스트에만 한정한다. 같은 서버 데이터의 카드·항목합계·내보내기가 맞는지 검사하고 서로 다른 기간/시점 값은 정의대로 대조한다.
- 모바일에서는 좌측 메뉴 접기, 카드 2열/1열, 패널 세로 재배치를 허용한다. 표만 내부 가로 스크롤하고 페이지 전체 잘림은 방지한다.
- 탭·메뉴·조회·상세·닫기·미저장 안내의 키보드 이동과 포커스를 확인한다. 탭 변경·계정 전환·로그아웃 때 다른 사용자의 데이터가 남지 않아야 한다.
- 연구원·책임자·담당자·관리자별 메뉴/건수/집계/직접 API를 검증한다. 담당자 기준 이미지에 맞추기 위해 권한을 확대하지 않는다.
- 이미지와 실제 화면의 차이는 역할·작은 화면·데이터·미구현 기능 등 사유를 기록한다. 새로운 디자인으로 임의 변경한 차이는 수정한다. 공개 검수 이미지는 가상자료만 사용한다.
