# 02 첫 구현 — 인증 데이터와 비공개 설정

2026-10-18 (Asia/Seoul). 기준 `e68d1ec`, 미커밋 변경 없이 `codex/phase-02-auth-foundation` 생성. 사용자의 02 다음 순서 진행 및 Google 준비·반환 주소 등록 완료에 따라 데이터 구조와 설정 연결을 구현했다.

## 구현 범위

- 기존 업무/사용자 ID와 01 SQL을 유지하고 5개 인증 테이블 추가, Drizzle 정의 동기화. 계정 감사는 필수 프로젝트 참조가 있는 기존 업무 감사와 분리했다.
- 이메일/제공자 식별자 중복, 다른 사용자 인증 연결의 세션, 8시간 초과 세션, 동시 세션 2슬롯 초과를 DB에서 거부한다. 수기 확인과 계정 감사는 추가형 이력을 보존한다.
- Google JSON은 사용자 지정 비공개 파일을 읽어 검사하고 dev/start에만 공급한다. 실제 경로·Client ID·Secret은 공개 파일에 기록하지 않았다. 새 라이브러리·의존성 버전·lockfile 변경 없음.
- 실제 로그인/반환 route·세션 서비스·관리자 등록·관리 화면·전체 권한 검수는 미구현. DB 구조/설정 로딩 검수를 로그인 성공으로 표시하지 않는다.

처음 일반 권한의 DB 검수는 비공개 설정 접근 실패로 실행되지 않았다. 허용된 권한으로 재실행했으나 DB가 정지되어 ECONNREFUSED가 발생했다. 문서의 전용 클러스터만 시작한 뒤 최종 검수가 통과했다. 첫 빌드는 Next.js 텔레메트리 설정 파일 쓰기 권한 오류(EPERM)였고 텔레메트리 비활성화 후 성공했다. 최초 실패를 삭제하지 않는다.

이번에 시작한 앱은 Ctrl+C로 종료했고 전용 DB도 정지해 작업 전 상태로 되돌렸다. 실제 DB 자료는 유지하고 생성한 무작위 시험 스키마만 명시적 객체 순서로 정리했다. 운영 DB·Notion·외부 업무자료 연동·main 병합은 변경하지 않았다.
