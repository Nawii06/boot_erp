# ERP 완성·실자료·향후 Notion 연계 통합 계획

2026-11-05 / Asia/Seoul. 사용자 요청은 기존 작업과 참조 검토를 합친 단계별 작업 프롬프트 구성이다. ERP 완성 후 실제 데이터 입력, 그 이후 예산사용내역/현황의 Notion 실적 연계를 후속 요구로 고지했다.

- STATUS·요구사항·최신 BC/EX 결정·04~10 단계/검수·운영 문서·참조 분석을 대조했다.
- P0~P7 구성완료, P8 실제 입력/대조, P9 후속 연계와 G1/G2/G3 판정 기준을 [계획](../completion-plan.md)에 작성했다. [통합/개별 프롬프트](../completion-prompts.md)를 제공했다.
- 05의 옛 사전/사후 분리 표현, 06의 지급 시 예약 감소 오해, 07의 금액 용어를 최신 단일 신청 정책에 맞췄다. 단계 구현 상태는 바꾸지 않았다.
- 09/10의 준비와 실행/최종 인수를 분리해 운영·복구/입력도구 검증을 실제 데이터 이전으로 옮겼다. 미답변 Q1~Q8과 기존 확정사항을 구분했다.
- [Notion 방향](../future-notion-integration.md)은 확정 요구/설계 제안/미결정을 분리한다. 원본 읽기 전용·금액/권한 유지, 외부 쓰기·전송 기능은 미구현이다.
- 요구사항 R-44~46, 결정 CP-01~03, 진입 링크·현재 상태·연혁을 갱신했다. 기존 작업 변경을 보존했다.

이번은 문서 작업이다. 앱·DB·실자료·Notion·운영 배포는 변경하지 않았다. 애플리케이션 테스트를 재실행하지 않았다. 문서 링크와 diff 공백·요구/순서·상태 일관성을 검사했으며 실제 명령 결과는 작업 보고에 남긴다.

최종 검증: `node scripts/check-docs.mjs`는 Markdown 73개·상대 링크 442개·누락 0, `git diff --check` 통과. 프롬프트 구조 검사에서 P0~P9 각 1개와 통합 프롬프트를 포함한 text 블록 11개를 확인했다. 최초 구조 검사 명령은 PowerShell의 백틱 처리 때문에 블록 수 assertion에 실패했고 문자열 구성을 바꾼 재실행은 통과했다. 문서 자체의 블록 누락은 아니었다. 별도 읽기 전용 교차검토에서 순서·미결정·기존 정책의 중대한 모순은 발견하지 못했다.
