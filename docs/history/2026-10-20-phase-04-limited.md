마이그레이션은 기존 테이블의 자료를 수정·삭제하지 않고 4개 테이블을 추가한다. 전체 마이그레이션은 5개, 업무 테이블 정의는 30개다. 격리 시험에서 SQL/Drizzle 열·타입·FK·CHECK와 반복 migration 무변경을 검수했다. 개발/시험 DB에 실자료를 입력하지 않았다. 테스트는 고유 시험 스키마의 가상 계정·금액·파일만 사용하고 종료 시 해당 스키마만 정리했다.

브라우저 시험에 필요한 3000 포트 확보 시 확인된 기존 로컬 Next 프로세스만 종료하고 검수 후 사용자용 서버를 복구했다. 사용자 브라우저·인증 앱을 자동 조작하지 않았다. 실제 Google 재로그인 인수확인은 이번 자동 시험 범위가 아니다.

## 실패·수정·재실행

1. 최초 타입 검사에서 제어흐름 반환형과 JSX unknown 타입 오류가 발생했다. 명시적 never 함수·boolean 조건으로 수정 후 통과했다.
2. 첫 DB 실행은 총 51건 중 48 통과·3 실패(부모 포함). 기준 확인 필요→잘못된 확인 완료 시험에서 같은 요청 ID에 다른 본문을 재사용해 예상 400 대신 정상적인 충돌 409가 발생했고 후속 시험이 연쇄 실패했다. 시험 요청 ID를 분리했으며 재실행 51건 모두 통과했다.
3. 첫 빌드는 Next의 사용자 설정 경로에 대한 sandbox EPERM으로 실패했다. 허용된 실행 권한과 telemetry 비활성화로 재실행해 통과했다.
4. 첫 UI 실행은 기존 앱이 3000 포트를 사용 중이어서 안전 중단했다. 대상 프로세스 확인 후 로컬 앱만 중단했다.
5. 다음 UI 실행은 설정 select의 접근성 이름을 찾지 못했다. 선택 상자에 명시적 aria-label을 추가하고 재빌드했다.
6. 그다음 UI 실행은 가상 계정 전환 중 기존 화면의 15초 세션 검사와 navigation이 경합해 `ERR_ABORTED`로 중단됐다. 시험 계정 선택 도우미에서 빈 페이지로 먼저 이동하도록 수정했다. 별도의 실제 동일 탭 계정 변경·로그아웃·뒤로가기 회귀검수는 유지했고 최종 전체 브라우저 검수가 통과했다.
