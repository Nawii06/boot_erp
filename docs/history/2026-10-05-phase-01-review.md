## 일상 개발 시 점검사항

- 앱 실행은 `scripts/app.cmd`와 [인수인계](../foundation.md)의 명령을 따른다. `scripts/toolchain.cmd run check`는 00단계 빈 DB 검사이므로 현재 테이블이 있는 DB의 상태 점검에 사용하지 않는다.
- `/api/session`의 401과 파일 경로의 404는 현재 설계대로다. 실제 로그인·업로드를 위해 임시 우회 코드를 추가하지 않는다.
- 앱에는 app 자격증명만 공급한다. owner용 `MIGRATION_DATABASE_URL`을 웹 프로세스에 함께 공급하면 연결을 거부한다. DB/비밀파일/원본은 저장소 밖에 둔다.
- 적용된 SQL 파일을 덮어쓰지 않는다. 최초 migration down은 데이터 보존을 위해 차단되어 있다. 공유 개발 DB를 초기화하지 말고 후속 SQL로 변경한다.
- 개발 서버와 프로덕션 서버를 같은 `.next`에 동시에 실행하지 않는다. 이번 검수 서버는 종료했다. DB 클러스터의 실행 상태는 변경하지 않았다.
