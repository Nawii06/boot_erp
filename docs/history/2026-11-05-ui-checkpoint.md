# 참조 ERP 화면 구성 중간 점검

후속: 사용자 통합 브라우저 로그인 후 대표 화면의 직접 관찰에 성공했다. 최신 분석은 [참조 ERP 검토](../reference-erp-review.md)를 따른다. 아래 접근 실패는 그 이전 시점 기록으로 보존한다.

2026-11-05 / Asia/Seoul. 사용자 요청: 현재 ERP를 https://sanhak-erp.ut.ac.kr/ 의 형태를 참고해 구성한다.

## 확인 범위와 한계

현재 앱의 portal.tsx, budget-panel.tsx/expense-panel.tsx 관련 화면 구조와 globals.css, ui-map.md, STATUS 및 04 단계 문서를 대조했다. 이번에는 기능 코드를 변경하지 않았다. 이전 세션의 로그인 후 공지창 확인은 인수인계 기록이며 이번 직접 관찰 결과가 아니다.

일반 웹 도구는 참조 URL 접근 실패. 브라우저 연결 호스트도 사용 불가였다. Windows 창 목록에는 Whale의 ‘메인화면’이 있었으나 창 연결은 `window id 1379488 no longer belongs to Naver_Whale; current owner is Naver_Whale` 오류로 실패했다. 창 목록을 새로 읽어 재시도하고 스킬의 기본 API로도 확인했지만 같은 오류였다. 따라서 로그인 상태·실제 URL·메뉴·색상·배치·업무 화면은 확인하지 못했다. 사이트 장애나 로그인 실패로 단정하지 않는다.

## 현재 ERP 점검

| 영역 | 코드에서 확인한 현재 구성 | 개편 제안 |
|---|---|---|
| 전체 틀 | 최대 폭 1100px의 중앙 정렬 포털, 상단 버튼형 업무 메뉴 | 넓은 업무 영역, 상단 공통 바와 좌측 업무 메뉴로 구성 |
| 메뉴 | 내 업무, 과제·비교과, 예산배정·변경, 지출 초안·증빙, 관리자의 계정/추가 확인 | 업무·과제 / 예산 / 지출 / 관리로 묶되 실제 권한과 제공 기능에 맞춰 노출 |
| 업무·과제 목록 | ul/li 목록과 선택 상세·편집 폼 | 검색조건 → 결과 건수·목록 → 선택 상세 순서를 일관되게 구성 |
| 예산 | 표, 분류·배정·변경 기능 | 금액 표의 정렬 유지, 조회 조건·변경 이력·첨부 영역을 구분 |
| 지출 | 초안 관리와 기준 설정을 같은 패널의 내부 메뉴로 제공 | 초안 목록과 상세의 기본정보·첨부·수정 이력을 구분, 기준 설정 위치를 명확히 표시 |
| 계정·보안 | 담당자/관리자 메뉴, 추가 본인 확인 후 관리 | 업무 메뉴와 관리 메뉴 구분, 추가 확인 상태와 만료 안내 유지 |
| 모바일 | 폼 폭 조정 및 예산표 내부 가로 스크롤 | 좌측 메뉴를 접을 수 있게 하고 표 스크롤을 화면 내부로 제한 |

이 표의 개편안은 현재 코드에 근거한 제안이다. 참조 대학 ERP에서 확인한 구조가 아니다.

## 제안하는 화면 틀

```text
BOOT ERP                         사용자 역할 · 세션 · 로그아웃
───────────────────────────────────────────────────────────
업무·과제      │ 업무 경로 / 현재 화면 제목
  내/전체 업무 │ 검색조건                         조회·초기화
  과제·비교과  │─────────────────────────────────────────────
예산 관리      │ 결과 건수                        허용된 작업
  배정·변경    │ 목록/금액 표
지출 관리      │─────────────────────────────────────────────
  초안·증빙    │ 선택 상세: 기본정보 / 첨부 / 이력
관리          │
  계정·기준    │
```

세부 메뉴 분리와 상세 탭은 후속 구현안이다. 기준 설정의 연구원 확인 완료 자료 조회, 책임자의 조회 권한은 유지한다. 통계 대시보드는 새로운 집계 API와 권한 검증이 필요한 별도 범위이므로 임의로 추가하지 않는다.

## 현재 문서·화면에서 정리가 필요한 부분

- ui-map.md 본문에는 연구원의 예산변경 미결정, 사전/사후 분리, 외부 공식 품의 필수 기록 등 종전 초안이 남아 있다. 최신 확정 정책으로 다시 작성해야 한다.
- portal.tsx 하단의 ‘지출 신청 화면·지급 기능은 후속 단계’ 문구는 초안·증빙 제공 여부를 명확하게 구분하도록 개선할 필요가 있다.
- 화면 전체에 같은 큰 h1 스타일이 적용된다. 로그인 안내와 실무 목록 화면의 제목·여백을 구분하는 안이 적절하다.

## 참조 확인 후 결정할 항목

1. 실제 상단 메뉴·좌측 메뉴·업무 탭의 관계.
2. 메인 화면의 정보 구획, 목록 검색조건과 표 밀도.
3. 과제/예산 목록과 상세의 이동 방식.
4. 지출 입력의 기본정보·증빙·처리 이력 배치.
5. 팝업/탭/상세 패널의 사용 범위와 작은 화면 처리.

메인 화면, 과제/예산 목록, 지출 입력/상세의 화면을 읽을 수 있어야 참조 대응표를 확정할 수 있다. 개인 이름·금액·계좌·문서 내용은 분석 산출물에 복사하지 않는다.

## 유지 범위와 검증

00~03 완료, 04 초안·비공개 첨부·기준 설정만 제공한다. 메뉴 개편으로 제출·검토·승인을 활성화하지 않는다. 초안은 예산 미차감이며 책임자는 조회 전용, 연구원 간 개별 자료 비공개, 서버 권한 검사를 유지한다. 대학 ERP/Notion 자료 저장·수정·자동 연동은 하지 않았다.

이번 변경은 점검 문서 추가이며 앱 테스트를 재실행하지 않았다. 문서 링크와 diff 공백 검사를 수행한다. 실제 참조 화면 확인 및 UI 적용·브라우저 회귀검수는 미완료다.
