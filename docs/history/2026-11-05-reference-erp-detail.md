# 참조 ERP 추가 상세 검토

2026-11-05 / Asia/Seoul. 사용자 요청: 참조 사이트를 더 세부적으로 학습할 필요 여부를 판단하고 가능하면 다시 상세히 검토한다. [초기 분석](../reference-erp-review.md)의 후속이다.

## 판단

추가 검토가 필요했다. 초기 분석은 공통 틀과 빈 입력 화면의 배치 중심이었다. 특히 과제 선택 전에는 예산 정보가 비어 있었고, 일반청구도 하단 내역을 선택해야 실제 상세·첨부가 입력 영역에 표시되는 구조였다. 이번에는 **과제 선택 → 예산 → 결의서 목록 → 청구서 상세 → 내역 선택 → 첨부 표시**를 읽기 전용으로 확인했다.

이제 기존 기능의 메뉴·조회·상세 화면을 개편하는 데 필요한 대표 구조는 확보했다. 전체 산학 ERP를 분석할 필요는 없으며, 예산변경 전후 화면·첨부 버전/처리 이력·다른 역할의 화면은 해당 상세 기능을 설계할 때 추가 확인한다.

## 직접 관찰한 구조

### 1. 선택 과제와 화면 문맥

- 메인 과제현황의 과제 행을 클릭하면 과제정보 화면에 해당 과제의 요약이 채워졌다.
- 같은 과제정보 안에서 예산·결의서 탭을 이동해도 선택 과제 요약이 유지됐다.
- 메뉴로 먼저 열었던 선택 전 화면과 과제 행에서 연 화면은 데이터 유무가 달랐다. 선택 전의 공란을 ‘자료 없음’으로 단정하면 안 된다.
- 열린 화면 탭에서 메인·과제정보·청구서 간 이동이 가능했다. 이는 화면이 함께 열려 있다는 관찰이며 모든 조회조건·미저장 폼 보존을 검증한 것은 아니다.

**BOOT ERP 적용안:** 선택한 과제·업무와 현재 조회 범위를 화면 위에 표시한다. 과제를 선택하지 않은 상태, 조회 결과가 없는 상태, 조회 권한이 없는 상태를 구분한다. 연구원에게 허용된 과제·업무 범위만 선택지로 제공한다.

### 2. 예산 화면

- 선택 과제 요약 아래 예산 탭이 있고, 최신 승인 관련 차수·일자·내용을 보여주는 요약 띠가 있었다. 과거 차수 선택·변경 전후 비교 동작은 확인하지 않았다.
- ‘예산총액’과 ‘예산내역’을 별도 구역으로 나눴다. 총액은 재원별 요약과 합계 행을 사용한다.
- 예산내역은 재원 필터, 비목 분류명·코드·명칭, 당초예산액(A), 변경후예산액(B), 이월액(C), 이자(D), 예산(E) 등을 표로 보여준다. 재원/분류의 상위 셀을 묶어 계층을 표현했다.
- 표는 많은 열과 행을 포함하며 내부 스크롤이 있다. 일부 열은 화면 범위 밖이므로 표 전체의 열 목록·합계 계산식은 확정하지 않았다.

**BOOT ERP 적용안:** 현재 서버가 제공하는 최초예산·현재예산·차감액·가용액의 의미를 유지하고 표 헤더와 요약을 분명히 한다. 참조의 이월·이자·재원·승인예산 모델이나 계산식을 새 업무 규칙으로 도입하지 않는다. 예산변경 상세에는 현재 구현된 전후 항목·사유·첨부·처리 이력을 구분해 배치하는 것이 적절하다.

### 3. 과제정보의 결의서 목록

- 결의서 탭에는 유형별 바로가기와 검색조건 패널이 있었다.
- 날짜 종류/기간, 진행구분, 결의서 유형, 재원/지출예산, 내용, 문서번호를 조회조건으로 제공했다. 조건 변경·새 검색은 수행하지 않아 실제 필터 동작은 미검증이다.
- 결과 표는 결의서 구분·번호·내용·금액·진행구분·신청일시 등의 열로 구성됐다.
- 임시저장·신청·신청(결재진행중)·보완요청·승인 등 상태가 문자와 색상으로 표시됐다. 저장·상신·승인 등 전이를 실행하지 않았으며 상태 정의와 차감 시점은 알 수 없다.
- 내역 행을 더블클릭하면 별도 ‘청구서(일반)’ 화면 탭이 열렸다. 목록 상단에는 상세조회/변경 등 작업 버튼도 있었다. 버튼의 제공 여부를 실제 수정 권한 검증으로 해석하지 않는다.

**BOOT ERP 적용안:** 상태는 색상과 문자로 함께 표현한다. 현재 구현은 초안 상태만 제공하므로 미구현 승인·지급 상태를 노출하거나 활성화하지 않는다. 초안 목록에는 현재 데이터에서 조회 가능한 정보만 배치한다. 목록 더블클릭 외에도 명확한 ‘상세 보기’ 버튼·키보드 경로를 제공하는 것이 좋다.

### 4. 청구서 상세와 내역 선택

- 상단에는 선택 과제·문서 신청정보·승인정보·대표내용·의견 등 문서 수준의 요약이 있었다.
- 중간에는 청구 입력 영역, 하단에는 청구내역 표가 있었다. 하단 내역의 선택 컨트롤을 누르자 화면이 해당 입력 영역으로 이동하면서 선택 내역을 표시했다.
- 선택 내역에 따라 내부 유형 탭과 필드가 달라졌다. 일반청구와 인건비(수당성 경비) 탭이 관찰됐다.
- 필드에는 예산 선택·예산잔액, 청구종류, 증빙 관련 표시, 금액, 일정, 내용, 기관 연계 부가정보 등이 있었다. 계좌·소득 등 후속 업무 정보도 포함되어 현재 BOOT ERP 범위와 차이가 크다.
- 청구내역 표에는 여러 항목과 합계 행이 있고 공급가액/부가세·증빙 관련 열도 관찰됐다. 이번 건이 한 행이었다고 문서당 한 항목으로 제한된다고 판단하지 않는다.

**BOOT ERP 적용안:** 초안의 공통 정보·첨부·수정 이력을 명확히 구분한다. 참조의 문서 아래 여러 청구내역을 다루는 구조는 현재 ‘신청 한 건에 예산항목 한 개’ 정책과 동일하지 않다. 계좌·소득·기관 연계 필드나 유형별 상세 규칙을 UI 참조만으로 추가하지 않는다.

### 5. 첨부와 이력

- 상단 입력 영역에는 큰 첨부문서 목록 영역과 첨부문서관리 버튼이 있었다. 하단 내역 선택 후 실제 첨부 파일명들이 목록 영역에 표시됐다.
- 청구내역 표에도 첨부문서 열이 있었고 증빙 관련 셀에는 밑줄 링크가 있었다. 표 내부 링크를 한 번 눌렀지만 새 첨부 목록/파일 열기가 확인되지 않아 추가 실행하지 않았다.
- 파일 다운로드·열기·추가·교체·삭제는 수행하지 않았다. 첨부문서관리 버튼도 변경성 관리창일 수 있어 열지 않았다.
- 파일 버전·교체 이력·서류별 검토 기록·반려/보완 왕복 이력은 확인하지 못했다.

**BOOT ERP 적용안:** 이미 구현된 비공개 첨부의 현재 파일·이전 버전·교체 이력·다운로드 권한을 명확히 표시한다. 이력 UI는 현재 코드·감사 데이터에 근거해 설계하며 참조에도 같은 기능이 있다고 쓰지 않는다.

## 적용 우선순위

| 순서 | 현재 기능에 적용할 항목 | 확보한 근거 | 남은 확인 |
|---|---|---|---|
| 1 | 상단/좌측 메뉴와 선택 과제 표시 | 공통 틀, 과제 선택 후 상세 탭 유지 | 역할별 노출은 BOOT 권한 기준으로 결정 |
| 2 | 검색·목록·상세의 일관된 구조 | 결의서 검색 패널, 표, 상세 탭 이동 | BOOT의 실제 검색 API 범위 |
| 3 | 예산 요약과 상세 표 분리 | 총액·비목별 내역, 분류 계층 | 변경 전후·다른 차수 화면은 미확인 |
| 4 | 지출 초안 기본정보/첨부/이력 분리 | 내역 선택 후 상세·첨부 표시 | 참조 버전/처리 이력은 미확인 |
| 5 | 빈 상태·키보드·작은 화면 개선 | 선택 전 공란, 큰 표의 내부 스크롤 | 미저장 안내·모바일 실제 동작 |

상단과 좌측을 정리하는 1차 개편을 더 미룰 이유는 없다. 반면 참조 ERP의 모든 결재·지급·회계 화면을 조사하거나 복제하는 것은 현재 목표를 넘어선다. 상세 미확인 기능은 후속 설계 시 필요한 범위만 조사한다.

## 기록과 검증 한계

- 조회/탭 이동/목록 선택/스크롤/표시 확대만 수행했다. 저장·수정·삭제·상신·승인·파일 다운로드를 수행하지 않았다.
- 실제 사람·과제명·식별번호·계좌·금액·증빙 파일명·소득 정보는 문서에 전사하지 않았다. 캡처 파일도 저장하지 않았다.
- 조사 후 메인 탭으로 돌아가고 이번에 변경한 브라우저 확대 비율과 VS Code 보조 사이드바 표시를 복원했다.
- 접근성 트리는 사용할 수 없어 화면을 확대해 관찰했다. 일부 열·버튼 이름과 세부 동작은 미확인이다.
- UI 코드·DB·업무 정책은 변경하지 않았다. 이번 검증은 문서 링크·공백 검사이며 앱 테스트는 재실행하지 않았다.
