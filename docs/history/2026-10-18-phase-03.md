# 03단계 예산배정·예산변경·금액 서비스

작업일: 2026-10-18. 사용자 요청에 따라 03단계만 구현·검수한다. 기준 커밋 `c22267a`에서 `codex/phase-03-budgets`를 생성했다. 시작 시 작업 트리는 깨끗했고 기존 02 완료·03 준비 이력을 보존했다.

## 구현 내용

- 분류 고유 코드·불변 버전·상하위 관계·적용일·비활성화와 배정 당시 분류 경로 스냅샷을 추가했다. 코드 문자열로 현재 부모를 추정하지 않는다.
- 예산 원금은 기존 불변 테이블에 유지하고 현재예산·신청 차감액·가용액·버전을 별도 관리한다. 사업명·연차·공통 기간은 BC-12에 따른다.
- 다중 변경행·필수 사유·전후 금액·비공개 첨부, 검토 시작·확정·반려·취소와 새 신청 연결을 구현했다. 확정 내용을 수정하거나 이전 첨부를 삭제하지 않는다.
- 프로젝트별 트랜잭션 잠금과 행 버전, 요청 지문·중복처리 키, 불변 감사로 금액과 상태 변경을 원자적으로 반영한다. 같은 요청 ID의 다른 내용은 충돌 처리한다.
- 업무 배정 기반의 지출 초안·신청·처리 시작·보완·승인·회수·반려·취소 공통 서비스를 추가했다. 단일 신청 즉시 차감, 복귀 시 복원, 승인 시 중복 차감 방지와 지급 상태 보호를 적용했다.
- 첨부는 변경신청에 귀속된 DB bytea로 저장한다. 5MiB 한도와 허용 확장자·선두 서명 검사, 권한 재검사·no-store·다운로드 강제 적용. 새 라이브러리는 추가하지 않았다.
- HTTP API와 예산 목록·상세·변경·분류 관리 화면을 연결했다. 연구원에게 공통 예산만 공개하고 타인 변경신청·첨부는 차단한다. 책임자는 조회만 가능하다.

로컬 비공개 Notion 참고표·JSON 구조를 확인했고 실자료·코드표를 DB에 자동 입력하지 않았다. Notion 쓰기·외부 연동·main 병합·운영 배포·04 이후 구현은 수행하지 않는다.

- `scripts/app.cmd run local -- test:db`: 41건 통과(부모 3건 포함). 기존 01/02 회귀와 신규 예산 하위 12건을 포함한다. Drizzle/SQL의 26개 테이블 열·타입·제약 수 대조 통과.
- `scripts/app.cmd run typecheck`: 통과.
- `NEXT_TELEMETRY_DISABLED=1`로 `scripts/app.cmd run build`: 통과.
- `scripts/app.cmd run local -- test:ui`: 기존 02 회귀 및 03 분류 등록·최초 배정·연구원 다중 변경·파일 제출·담당자 검토/확정·권한 있는 다운로드 통과. 데스크톱/모바일 가상 스크린샷을 확인했다.
- `scripts/app.cmd run local -- migrate`, `migrate:test`: 각각 1건 적용, 총 migration 4개·업무 테이블 26개.
- 개발·시험 제한 앱 계정으로 새 예산 테이블을 읽기 전용 조회했다. 두 환경 모두 예산배정·분류코드·첨부 0건이며 실자료 미이관과 런타임 접근 권한을 확인했다.
- 사용자용 서버를 기존 비공개 Google 설정으로 재실행하고 `scripts/app.cmd run test:http`를 통과했다.
- `scripts/app.cmd run check:docs`: Markdown 57개·상대 링크 276개, 누락 0건. `git diff --check`: 공백 오류 없음.
- 공개 변경 파일 28개를 비공개 참고표의 원문 항목명·프로젝트명·원본 URL과 대조해 일치 0건을 확인했다. `custom_ref`와 가상 브라우저 산출물은 Git 제외이며 비공개 원본 추적 파일은 없다.

처음에는 대용량 base64의 반복 정규식 검사에서 503이 발생했다. 선형 문자 검사와 디코드·재인코드 대조로 수정한 뒤 동일 초과크기 검수가 400으로 통과했다. 최초 타입 검사에서 JSX 괄호와 TypeScript 입력 좁히기 오류를 수정했다. 일반 권한으로는 저장소 밖 DB 설정 접근과 Git 브랜치 생성이 차단되어 필요한 권한으로 재실행했다. 기본 빌드의 사용자 텔레메트리 설정 파일 접근 실패는 텔레메트리를 끄고 해결했다.

브라우저 검수는 기존 서버의 포트 점유를 감지해 중단했다. 확인한 ERP 프로세스만 잠시 종료하고 격리 시험 서버로 재실행했다. 선택 상자의 이름에 옵션 내용이 섞여 정확한 레이블 선택이 실패한 것을 발견하여 명시적 접근성 이름을 추가했다. 수정본 재빌드·브라우저 재검수 후 통과했다. 실제 개발 계정으로 자동 로그인하거나 실제 예산을 시험 자료로 사용하지 않았다. 시험 서버·스키마는 정리하고 사용자 서버를 복구했다.

## 범위와 남은 작업

03 구현·가상 검수 완료로 판정한다. 최종 작업 브랜치 커밋·푸시 SHA는 사용자 결과 보고에 명시한다. main 병합·운영 배포는 하지 않는다.

최초 커밋은 Git 작성자 설정이 없어 실패했고 원격에는 기준 커밋의 작업 브랜치만 생성됐다. 기존 저장소 이력의 Codex 작성자 정보를 해당 커밋 명령에만 지정하여 재시도한다. 전역 Git 설정은 변경하지 않는다.

지출 신청·증빙 전체 화면, 실제 지급 입력·환입·분할 지급, 실자료 이관, 운영 성능·악성코드 검사·백업 복구는 완료 범위가 아니다. 지급 후 취소 차단은 가상 지급 상태를 DB에 구성해 검사한다. B-10/B-11/W-05는 공통 서비스 범위이며 후속 화면에서 다시 연결 검수한다.

03 이후에는 04단계 단일 신청·증빙 화면을 준비하면서 D-07 유형별 증빙·단가·기한과 이후 D-08/D-09 정책을 필요한 범위에서 확인한다. 이미 확정된 BC-01~BC-13은 반복 승인받지 않는다.
