# 02단계 로그인·열람 정책 결정 반영

작업일: 2026-10-05 (Asia/Seoul). 기준: `36ca942a45f33669ac6abd7fe1ee99d72f56c7c0`, 미커밋 변경 없이 `codex/phase-02-policy` 생성. 사용자 요청은 D-04/D-05 항목별 방침 반영과 세션·복구 결정을 위한 설명이다.

## 반영한 확정 사항

1. Google 연동 로그인, 향후 대학 SSO 교체 가능 구성.
2. 이메일 기준 계정 관리, 담당자 우선·부재 시 관리자 대행 가능.
3. 계정당 역할 1개.
4. 연구원 간 다른 연구원의 업무·자료 비노출. 같은 프로젝트의 요약 공유 제안도 대체.
5. 책임자는 담당 과제·비교과 전체 내용 조회. 조회 전용·승인 제외 유지.
6. 동일 업무 재배정 시 과거 자료 전체 승계. 전임자 명의·행위 이력은 보존하고 미이관 업무 접근은 부여하지 않음.

사용자의 동일 업무/내용 표현을 재배정 대상 업무 전체의 승계로 해석했다. 같은 사람의 이메일 변경과 다른 사람에게의 업무 인수인계를 분리했다. 후임의 개인 계정은 별도로 유지하고 업무 ID와 과거 행위자를 덮어쓰지 않는 구성이다.

## 미결정과 기술 방침

세션·복구 S-01~S-10과 사전등록 방식·관리자 계정/역할 보안 변경 범위·허용 Google 이메일 A-01~A-03은 [결정 안내](../auth-policy.md)에 제안으로 정리했다. 사용자에게 다시 Google 제공자·단일 역할·연구원/책임자 열람의 이미 확정된 사항을 묻지 않는다. 기관 세션 기준이나 권고 수치의 승인을 가정하지 않는다.

이메일 관리 화면과 불변 ERP 내부 ID, 검증된 제공자 subject 연결을 구분하는 구현 방침을 기록했다. Google ID 토큰 검증 및 이메일 소유 확인의 한계, SSO 교체 시 업무·감사 참조 보존, ERP 세션과 Google 세션 분리를 공식 문서로 확인했다. 근거 링크는 정책 안내에 포함한다.

## 변경·검수 범위

- AGENTS, 요구사항, 권한표, 결정 AC-01~AC-07, STATUS, 02 작업서, 화면 초안, 검수표를 최신 정책에 맞췄다. 01 인수인계에는 기존 공통 함수가 새 정책의 완성 구현이 아니라는 설명을 추가했다.
- A-06~A-11을 예정 검수로 추가했다. 문서만 변경했으므로 앱 테스트를 재실행하거나 새 정책의 권한 검수 통과를 선언하지 않는다.
- Google OAuth client/secret 생성·외부 로그인 연결·DB/코드 변경·운영 배포·main 병합을 수행하지 않았다. Notion 변경 및 홈페이지/대학 ERP 업무자료 자동 연동도 없다.
- 과거 D/P 표와 01 검수 기록은 당시 이력으로 보존한다. 최신 상태는 AC 기록과 STATUS를 따른다.

문서 검수 결과: `scripts/app.cmd run check:docs` 통과(Markdown 38개, 상대 링크 154개, 누락 0). `git diff --check` 공백 검사 통과. 변경 범위는 정책·설계·진행/연혁 문서이며 실제 개인정보·인증정보를 추가하지 않았다. 애플리케이션 테스트는 코드 변경이 없어 재실행하지 않았다. 원격 반영 결과는 확인 후 기록한다.

## 다음 작업

사용자에게 세션/복구의 의미와 권고안, 계정 보안 경계의 추가 선택을 안내한다. 확정 답변 후 정책 의존 설정을 적용하고 Google OAuth의 비공개 실행 설정을 준비하여 02 기능 구현·검수를 진행한다. 대학 SSO 실제 연결은 기관 사양 확인과 전환 검수 후 별도 수행한다.
