# 03 준비 마무리 — 신청 전이·Notion 배정자료

작업일: 2026-10-18. 사용자 후속 답변을 확정 정책으로 기록하고 지정 Notion 자료를 읽기 전용 참고했다. 이번은 준비 문서·비공개 참고표 정리이며 앱·DB 구현이 아니다.

## 사용자 확정 사항

- 연구원 본인 회수는 담당자 처리 전까지 허용한다.
- 담당자의 보완 요청은 신청 효력과 기존 차감을 유지하며 상태만 보완으로 변경한다.
- 반려·취소 후에는 차감을 복원하고 수정·재신청할 수 있다. 승인 후 취소는 지급 전 담당자·관리자만 수행한다.
- 신청 금액 변경은 신청 전 복귀 → 기존 금액 복원 → 수정 → 현재 잔액 검사 후 재신청·새 금액 차감 순서다.
- 기존 예산변경 양식은 첨부파일로만 활용한다. 사유·전후 금액·첨부 필수는 유지하고 실사용 후 필요 시 변경한다. 양식 자동 추출·화면 재현은 추가하지 않는다.

담당자 처리 시작을 서버에 기록하고 회수와의 경합을 제어하는 것, 지급된 건의 일반 취소를 차단하는 것은 정책 구현 기준으로 명시했다. 보완 제출을 새 금액 신청으로 처리하지 않는다. BC-07~BC-10, R-31~R-34 및 예정 검수 B-10/B-11/W-05를 연결했다.

## Notion 조회 범위·결과

`notion: notion-research-documentation` 스킬에 따라 지정 페이지를 직접 fetch하고 프로젝트·예산배정 스키마를 확인한 뒤 필요한 열만 읽기 전용 SQL로 조회했다. 예산변경요청은 스키마와 상태별 건수만 확인했다. 쓰기·수정·삭제·댓글·뷰·자동화 도구는 호출하지 않았다.

- 프로젝트 14행: 산공 6개·비교과 7개·이름 및 구분 없는 행 1개. 마지막 행은 ERP 사용 대상에서 제외하고 원본 그대로 유지.
- 예산배정 73행: 프로젝트 관계와 행별 금액, 원래 분류명을 확보. 프로젝트/배정 응답 모두 `has_more=false`.
- 각 배정이 유효 프로젝트 1개와 연결됨을 대조하고 원 단위 정수·행 URL 중복·프로젝트별 합계를 검사했다.
- 변경요청 승인 행의 존재를 확인했지만 원래 배정금액에 변경이 이미 반영됐는지는 확인하지 않았다. 변경 차액을 자동으로 더하지 않는다.
- 날짜 누락·종료일 부재가 있어 전체 적용 사업연차·사용기간은 확정할 수 없다.
- 기존 PDF의 세세목과 Notion 명칭이 일대일로 연결되지 않는 일부 항목은 후보·확인 대상으로 분리했다. 원명·금액을 보존하고 임의 분할·균등 배분·강제 합계 조정을 하지 않았다.

상위 페이지 응답은 as-of 2026-10-16T08:50:08.996Z를 표시했다. 본 검토를 최신 실시간 동기화, 전체 워크스페이스 감사, 지급/가용잔액 검증으로 표현하지 않는다. 연락처·개별 사용/지급 내역·첨부는 조회하지 않았다. 조회된 배정합계는 지급액이나 가용잔액이 아니다.

실제 이름·금액·원본 URL·관계 ID·행별 매핑 후보는 Git 제외 로컬 참고표/JSON에 저장했다. 원문 접근 위치와 실제 금액은 공개 문서에 복사하지 않았다. 기존 PDF와의 기준 범위·시점 관계는 별도 확인 대상으로 기록했다.

## 검수·구현 상태

문서 링크·범위·현재 상태 일관성, 로컬 참고자료 합계·관계·중복, Git 제외 및 커밋 대상을 검사했다. `scripts/app.cmd run check:docs`는 로컬 Markdown 53개(비공개 참고표 2개 포함)·상대 링크 240개 누락 없음, `git diff --check`는 공백 오류 없음이다. 참고자료의 유효 프로젝트 관계·중복 없는 73행·원 단위 정수·프로젝트별 합계 대조를 통과했다. `git check-ignore`로 로컬 참고표/JSON 제외를 확인했고 `git ls-files custom_ref` 결과는 비어 있다.

최초 보조 합계 검사는 PowerShell의 JSON 배열을 중첩 배열로 감싼 비교식 때문에 실패했다. 배열을 먼저 변수로 받아 비교하도록 검수 명령만 고친 뒤 재실행해 통과했다. 원자료·금액은 변경하지 않았다. 앱·DB를 변경하지 않았으므로 애플리케이션 테스트·마이그레이션은 미실행이며 예정 검수를 통과로 표시하지 않는다.

가상 자료로 03 예산배정·변경·첨부·신청 차감/복원 공통 기능을 구현할 기준은 확보했다. 실자료 입력 전 남은 확인은 PDF/Notion의 적용 범위, 예산기간, 일부 세세목 연결 및 배정액에 변경이 반영됐는지 여부다. 전체 배분표를 다시 작성하도록 요구하지 않는다.

지급 후 정정·환입과 추가/분할 처리는 후속 단계에서 정리한다. 02 완료를 유지하며 03 기능 구현·실자료 DB 입력·main 병합·운영 배포·Notion 변경은 수행하지 않았다.
