# ERP 구성 실행 진행표와 최종 점검 목록

2026-11-06 / Asia/Seoul. 사용자 통합 프롬프트로 P0~P7 실행을 시작했다. 기존 00~03/04 제한 구현·환경 검증은 [STATUS](STATUS.md)의 과거 증거로 보존하며 현재 코드/환경과 대조한다. 새 기능과 검수는 아래에서 별도로 추적한다.

같은 날 후속 요청: Google 없는 로컬 임시 접속을 PREVIEW-01~03으로 별도 구현한다. [임시 접속 안내](local-preview.md)를 따르며 실제 Google 인증 검증/P0·G1 완료를 대체하지 않는다. 실제 자료 입력/P8 및 Notion/P9는 계속 미착수다.

실행 절차: [자동 확인·최종 점검 규약](execution-checks.md). 통합 프롬프트 실행 시 에이전트가 실제 명령/관찰 결과에 따라 이 파일을 갱신한다. 진행표 자체가 자동 테스트나 상시 모니터링 프로그램은 아니다.

## 1. 상태와 증거 규칙

- `not_started`: 실행 전. `in_progress`: 구현/검사 중. `step_passed`: 즉시 필수 통과·최종 검수 대기. `verified`: 해당 범위 최종 검수까지 통과. `blocked`: 필요한 정책/비공개 환경/선행조건 부재. `failed`: 필수 실행 결과 실패.
- 검사 결과는 `passed/failed/not_run/deferred/stale`로 별도 기록한다. 구현 상태와 검사 결과를 혼용하지 않는다. 전체 완료는 `step_passed` 개수만으로 계산하지 않는다.
- 증거에는 실행일시·명령/관찰·종료코드·검수 ID/범위·대상 코드/스키마/환경·실행 결과·정제된 기록 링크를 남긴다. HEAD와 미커밋 변경의 식별도 포함하고 민감한 원시 로그는 공개하지 않는다.
- 이전 증거 재사용 시 근거·무변경 범위·재확인 시점을 적는다. 관련 코드/정책/스키마/의존성/환경 변경 후에는 영향받은 증거만 `stale`로 전환한다.
- 적용하지 않는 항목은 사용자 결정/정책 근거로 제외 범위를 기록한다. 실행하지 않은 필수를 적용 제외로 돌리지 않는다.

## 4. 판정 요약

- 현재 실행 범위: **P0~P7 독립 구현·로컬 검증과 F0 판정 수행. 실자료/Notion/운영 전환은 미실행**.
- G1: **미완료**. 실제 Google 인증/원래 키, 운영 대상·합의 규모/보존/검역·복구목표와 해당 필수 검증이 남았다. G2/G3: 미착수.
- 다음 시작점: P0 실인증 및 P7 운영 외부 조건을 준비하고 영향받은 필수만 재검사한다. 이미 통과한 P2~P6를 처음부터 반복하지 않는다.
- P8 준비: G1 해소 후 실제 기준값/연구인력 범위, 입력 대상·기준일·원본/대조 책임·수기/배치·기초잔액 방식을 확정하고 비공개 백업/dry run/대조 뒤 입력한다. 이번 실행에서 시작하지 않았다.
- 자동 확인 가능한 검사와 정책/외부 확인이 필요한 항목을 분리해 기록한다. 문서 항목 수나 완료 체크 비율만으로 G1을 통과시키지 않는다.
