# Google 없이 보는 임시 로컬 미리보기

2026-11-06 / Asia/Seoul. 실제 Google 계정이나 업무자료 없이 화면·역할·신청 흐름을 살펴보기 위한 가상 환경이다. 일반 실행에서는 꺼져 있으며 전용 실행기로 켠 localhost 미리보기에서만 임시 접속을 제공한다. 실제 Google 로그인 검수나 G1 운영 인수를 대신하지 않는다.

## 실행과 접속

저장소 루트에서 실행한다. 프로젝트 지정 Node/npm을 선택하는 Windows 실행기를 권장한다.

현재 코드의 프로덕션 빌드가 필요하다. 아직 빌드하지 않았거나 코드가 바뀌었다면 먼저 `.\scripts\app.cmd run build`를 실행한다. 실행기는 빌드 존재를 확인하며 매번 자동 빌드하지 않는다.

작업 폴더에 `.env`, `.env.local`, `.env.production`, `.env.production.local`이 있으면 실행을 거부한다. Next가 이 파일을 다시 읽어 운영/owner 설정을 주입하는 것을 막기 위한 제한이다. `.env.example`은 해당하지 않는다. 기존 설정 파일을 삭제하거나 공개하지 말고 담당자와 별도 미리보기 설정을 준비한다.

```powershell
.\scripts\app.cmd run preview
# 지정 Node/npm이 적용된 터미널에서는 npm run preview 도 같은 명령이다.
```

실행기가 별도 가상 스키마와 계정을 준비하고 Next 서버의 Ready 표시를 확인한 뒤 [로컬 미리보기](http://localhost:3000)를 연다. `preview-starting`은 시작 요청이며 서버 준비 완료와 다르다. 3000 포트에 다른 서버가 실행 중이면 먼저 그 서버의 작업을 확인하고 해당 터미널에서 정상 종료한다. 다른 프로그램을 미리보기 정리 대상으로 간주하지 않는다.

첫 화면에서 역할을 선택하고 **임시 접속**을 누른다. 기본 선택은 담당자다. 연구원·과제책임자·관리자도 선택할 수 있다. 다른 역할을 확인하려면 현재 역할에서 로그아웃한 뒤 다시 선택한다. 이 화면에서 Google 비밀번호·인증 코드·실제 계정 정보를 입력하지 않는다.

| 역할 | 미리보기에서 볼 범위 |
|---|---|
| 담당자 | 전체 가상 업무·예산·신청 검토·실청구/지급 기록 |
| 연구원 | 본인 가상 배정 업무·신청·개인 지급 실적. 동료 자료는 비공개 |
| 과제책임자 | 담당 과제의 가상 자료 조회. 제출·승인·지급 기록 변경 불가 |
| 관리자 | 관리자에게 허용된 가상 관리·대행 화면. 실제 운영 권한을 부여하는 기능이 아님 |

화면 상단에 **임시 접속·가상자료**와 종료 예정시각을 표시한다. 기존 ERP의 유휴 15분/최대 8시간 세션 규칙도 적용된다. 전체 미리보기의 유효기간은 시작 후 최대 8시간이며, 다시 접속해도 이 환경의 종료 예정시각을 늘리지 않는다.

## 초기 가상 데이터와 사용 범위

담당자 대시보드의 초기 예시는 현재예산 100,000,000원, 유효 신청 차감액 40,000,000원, 가용예산 60,000,000원, 실제 지급총액 25,000,000원이다. 지급은 기존 신청 차감액에서 다시 빼지 않는다. 역할·기간·필터와 가상 변경에 따라 표시값은 달라질 수 있다. 이 숫자는 운영 초기예산·기관 단가·실제 집행 실적이 아니다.

화면을 둘러보거나 **가상 값과 가상 파일만으로** 초안·첨부·신청·보완·지급/환입 기록을 시험한다. 실제 개인정보·과제명·계좌·금액·증빙·키를 넣지 않는다. 미리보기 스키마의 변경은 보관할 실제 업무자료가 아니며 정상 정리 후 사라진다. 세부 사용법은 [사용자 안내](user-guide.md)를 따른다.

## 종료

다른 터미널에서 다음을 실행한다.

```powershell
.\scripts\app.cmd run preview:stop
# 지정 Node/npm이 적용된 터미널에서는 npm run preview:stop
```

정상 종료는 미리보기가 만든 실행표식을 확인해 해당 서버와 임시 스키마만 정리한다. 8시간 제한이 지나면 정상 실행기의 미리보기는 자동 종료된다. 강제 종료·PC 재부팅·연결 오류로 정리를 끝내지 못했다면 가상 스키마나 실행표식이 남을 수 있다. 새 실행이나 종료 명령의 고정 오류 안내를 확인하고 운영 담당자에게 정리를 요청한다. public·개발 DB·기존 시험 스키마를 직접 초기화해 해결하지 않는다.

`preview:stop`의 `stop-requested`는 살아 있는 실행기에 종료를 요청했다는 뜻이다. 원래 실행 터미널의 종료/정리 결과까지 확인한다. 이 명령 자체는 PID로 프로세스를 죽이거나 DB에 접속하지 않는다. 실행기가 이미 비정상 종료됐다면 요청만으로 남은 스키마가 정리되지 않는다.

## 격리와 인증 경계

- 서버는 loopback으로 열며 앱 주소는 `http://localhost:3000`이다. 공개 URL·외부 호스트·공유 프록시용 인증 기능이 아니다.
- 실행기는 `boot_erp_test` 안의 전용 `boot_preview_<무작위 UUID>` 스키마를 사용한다. public이나 개발 DB를 미리보기 자료 저장소로 사용하지 않는다. 웹 프로세스는 제한된 test app 계정으로 실행한다.
- 임시 접속은 고정 가상 이메일 `preview-<역할>@erp.example.invalid`에 연결된 네 역할만 선택한다. 임의 이메일·사용자 ID·역할을 제출해 로그인하는 API가 아니다.
- 접속 요청은 미리보기 플래그·정확한 앱 주소/DB/스키마·유효기간·요청 출처와 가상 계정의 등록/확인 상태를 검사한다. 기존 ERP 세션 발급·권한 검사 경로를 사용하며 실제 Google 계정으로 인증된 것처럼 표시하지 않는다.
- 일반 실행의 Google 인증, 관리자 관리, 세션 제한은 유지된다. 미리보기 플래그를 일반 개발/운영 설정이나 저장소의 `.env.example`에 상시 설정하지 않는다.
- 브라우저에 DB/owner 자격증명을 보내지 않는다. 종료 표식·비공개 접속 설정·키·원시 로그를 대화나 공개 저장소에 붙여넣지 않는다.
- 실행 표식은 gitignore된 `test-results` 아래에 두며 파일 ACL은 현재 Windows 사용자와 SYSTEM만 허용한다. 표식에 접속 비밀번호·세션 토큰·Google 키를 저장하지 않는다. 전용 가상 스키마와 일치하는 무작위 식별자·시작/만료 정보만 사용한다.

## 제한과 오류 대응

종료 시간이 지났거나 미리보기 조건이 맞지 않으면 임시 접속이 거부된다. 화면 새로고침이나 정상 재실행으로 상태를 확인하되 만료시간·스키마·쿠키를 수동 조작해 연장하지 않는다. 동시에 같은 가상 역할을 여러 브라우저에서 사용하면 기존 계정당 2세션 제한에 걸릴 수 있다. 해당 가상 역할의 이전 창에서 로그아웃한 뒤 다시 접속한다.

이 미리보기는 실제 OAuth 파일·기존 암호화 키를 복구한 것이 아니다. 운영 배포 대상·규모·보존/검역·RPO/RTO·실제 인증 검증의 미완료 상태는 그대로다. 실제 자료 입력은 G1 이후 지정한 P8 범위에서, Notion 연계는 G2 이후 P9에서 별도로 수행한다. 기존 Notion 원본은 읽기 전용이며 이 미리보기는 Notion에 연결하거나 전송하지 않는다.

이 문서는 구현 계약과 현재 UI/인증 소스를 바탕으로 작성했다. 실제 실행·브라우저·종료/만료·격리 가드 검사 결과는 해당 구현 담당자의 최종 검증 기록으로 확인한다.

## 이번 준비 검증 범위

구현 담당자로부터 임시 인증의 설정/DB 세션 검사 8건, fixture-only 검증, owner/Google/PG 환경 미전달·자체 스키마 정리·stop 요청만 수행하는 경로, 원래 public 상태 불변 및 dotenv 거부 검사가 통과했다는 결과를 전달받았다. 가상 분류는 새 예산배정 화면에서도 사용할 수 있도록 3계층으로 준비했다.

문서 작성과 보안 소스 검토 담당자는 서버나 브라우저를 실행하지 않았다. fixture-only와 인증 검사 통과를 실제 서버 기동·브라우저 접속·8시간 경과·정상 종료의 관찰 결과로 확대하지 않는다. 그 실행 결과는 최종 미리보기 작업 기록에서 별도로 확인한다.
