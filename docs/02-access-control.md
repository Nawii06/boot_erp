# 역할·접근권한 설계

2026-10-05 사용자 답변으로 Google 로그인·이메일 계정 관리·단일 역할과 연구원 격리·책임자 전체 조회·재배정 자료 승계를 확정했다([AC-01~AC-06](07-decisions.md)). 세션·복구와 계정 관리의 세부 보안 경계는 [추가 안내](auth-policy.md)의 미결정이다. 01단계는 공통 경계만 구현했으며 아래 최신 정책은 아직 코드에 적용·검수되지 않았다.

과제책임자의 확인 여부는 청구 진행의 선행조건이 아니다. 책임자의 전체 열람은 담당 과제·비교과의 신청·청구·증빙·처리·지급·정산 내용을 포함하며 계정 비밀·서버 설정은 포함하지 않는다. 관리자의 권한은 업무 절차·기록을 건너뛰는 별도 무기록 통로를 의미하지 않는다.

## 계정과 배정

- `users`: 로그인 주체, 역할, 활성 상태. 역할명과 연구원 직책/학생 여부를 동일시하지 않는다.
- `people`: 학생·교수·외부인 등 참여자 정보. 로그인 계정이 없어도 참여자로 등록 가능.
- `project_memberships`: 업무와 사용자/참여자 연결, 업무상 역할, 적용기간·활성 상태.
- 계정당 시스템 역할은 1개로 확정했다. Google/대학 SSO 인증 연결 수와 ERP 시스템 역할 수를 혼동하지 않는다.
- 계정은 이메일로 등록·검색·관리하고 서버에서 검증한 Google 식별자를 불변 내부 계정 ID에 연결한다. 담당자가 우선 관리하고 관리자가 대행할 수 있다. 대학 SSO로 전환해도 같은 사람의 내부 계정과 업무 이력을 유지한다.
- 배정 해제·계정 정지 즉시 새 요청을 차단하고 기존 기록의 작성자 식별정보는 유지한다.

## 본인 청구와 공동업무

작성자·신청자·현재 처리 연구원을 구분한다. 담당자가 대행 입력하면 실제 입력자와 대행 대상자를 함께 기록한다. 연구원 간에는 다른 연구원의 업무·자료를 공개하지 않는다. 같은 프로젝트 배정만으로 동료 업무의 목록·제목·상세·파일·합계·검색·출력 접근을 허용하지 않는다. 프로젝트 내부의 업무 배정/인수 범위도 서버에서 검사해야 한다.

책임자는 담당 과제·비교과 전체 자료를 조회하며 연구원별 격리 규칙을 책임자에게 그대로 적용하지 않는다. 이전 요약 중심/상세 증빙 미결정 제안은 AC-05로 대체한다. 업무 원본 수집의 적정성·공개 저장소 금지 원칙은 유지한다.

인수인계는 재배정된 동일 업무의 전체 과거 자료를 후임에게 연결한다. 다른 사람에게 넘기는 인수인계는 전임 계정의 이메일을 후임 이메일로 덮어쓰는 방식으로 처리하지 않는다. 별도 후임 계정에 배정을 이전하고 원 작성자·전임자·시각·변경 사유를 보존한다. 같은 사람의 이메일 변경/SSO 전환은 동일인 확인 후 인증 연결을 바꾸는 별도 절차다. 후임의 쓰기 권한은 역할·업무 상태에 따르고 책임자는 계속 조회 전용이다.

## 서버 검사 지점

목록, 상세, 검색, 자동완성, 집계, 엑셀/CSV, 파일 미리보기·다운로드, 임시 다운로드 URL 발급, 일괄작업을 각각 검사한다. 클라이언트가 보낸 프로젝트 ID·작성자 ID를 그대로 신뢰하지 않는다. 예산항목과 집행 건의 프로젝트가 같은지 서버/DB에서 검사한다.

업무 역할과 메뉴 숨김은 별개다. 읽기 전용 사용자가 직접 쓰기 API를 호출해도 거부해야 한다. 다른 사용자의 캐시·다운로드 결과를 재사용하지 않는다.

## 검수 연결

검수 A-01~A-11과 F-01~F-03을 사용한다. 관리자 우회 접근도 감사기록에 남긴다. 운영 DB 관리자 자체의 모든 행위를 애플리케이션만으로 막을 수 있다고 표현하지 않으며, 별도 운영 감사·백업으로 보완한다.
