# 산학 ERP 참조 화면 분석과 적용안

2026-11-05 / Asia/Seoul. 참조: https://sanhak-erp.ut.ac.kr/ . 사용자가 직접 로그인한 VS Code 통합 브라우저를 읽기 전용으로 관찰했다. 이전 연결 실패와 달리 이번에는 실제 화면을 확인했다.

후속 상세 검토: [과제 선택·예산·결의서·내역별 첨부 분석](history/2026-11-05-reference-erp-detail.md). 초기 배치 관찰에 더해 실제 과제/내역을 선택한 조회 문맥을 확인했다. 아래 미확인 항목 중 일부를 해소했으며 최초 관찰 결과와 후속 결과를 구분한다.

## 직접 확인한 범위

- 메인화면: 과제 목록과 검색·페이지 이동, 개인 처리 현황, 공지·공고·알림, 달력 등 여러 구획을 배치한 포털이다. 넓은 화면에서는 과제 목록과 개인 현황을 나란히 배치하고 아래에는 여러 카드가 이어진다. 좁은 편집기에서는 가로 잘림과 세로 이동이 발생했다.
- 공통 틀: 로고·사용자 영역, 파란색 상단 업무 분류, 짙은 파란색 열린 화면 탭, 좌측 사용자/세부 메뉴, 오른쪽 업무 본문으로 구성된다. 업무 분류를 선택하면 좌측 메뉴와 활성 화면이 함께 바뀌고 기존 열린 화면 탭은 남는다.
- 과제정보: 상단 과제 검색, 선택 과제 요약, 여러 상세 탭, 접을 수 있는 제목 띠, 라벨/값을 행과 열로 배치한 기본정보, 하단 관계 정보 표를 확인했다.
- 지출관리의 일반청구(new): 상단 과제 검색과 요약, 청구내역 구역, 내부 탭, 행 단위 입력 폼, 날짜/선택/검색 보조 컨트롤, 큰 내용 입력 영역, 하단 청구내역 표와 작업 버튼 배치를 확인했다. 하단까지 스크롤했으며 입력·저장·상신하지 않았다.

화면 글자가 작은 데다 접근성 트리를 읽을 수 없어 모든 필드·탭 이름을 정확하게 판독하지 못했다. 불명확한 이름은 추정해 전사하지 않았다. 실제 계정·과제·금액·공지 원문·연락처는 이 문서에 옮기지 않았으며 화면 캡처 파일도 저장소에 저장하지 않았다.

## 현재 기능과의 대응

| 참조에서 확인한 요소 | 현재 BOOT ERP | 적용 제안 | 경계 |
|---|---|---|---|
| 상단 업무 분류와 좌측 세부 메뉴 | 상단 버튼으로 모든 메뉴 나열 | 상단 업무/관리 구분, 좌측 업무·과제/예산/지출/설정 메뉴 | 현재 역할별 허용 범위 유지 |
| 열린 화면 탭 | 단일 tab 상태, 화면 이동 시 선택 상세 초기화 | 우선 현재 화면 표시와 경로 제공, 다중 작업 탭은 후속 적용 | 폼 미저장·계정 전환·세션 종료 시 데이터 정리 설계 필요 |
| 메인 과제 목록·개인 현황 | 로그인 후 업무 목록 | 권한 있는 업무·과제 목록과 바로가기 중심의 홈 | 새 승인 통계·공지·달력 기능을 구현 완료처럼 표시하지 않음 |
| 과제 검색·요약·상세 탭 | 과제 목록 아래 상세와 편집 폼 | 검색/목록과 선택 상세를 나누고 기본정보·참여자·이력 구역 정리 | 연구원 격리·책임자 조회 전용 유지 |
| 표 형식 상세와 접는 구역 | 긴 세로 폼 | 큰 화면에서 라벨/값 2열, 좁은 화면에서는 1열 | 입력 순서와 키보드 이동 유지 |
| 청구 입력과 하단 내역표 | 지출 초안 목록·폼·첨부/이력 | 초안 검색·목록, 선택 초안의 기본정보/첨부/이력으로 구성 | 일반청구 화면의 지급·계좌·결재 규칙은 도입하지 않음 |
| 파란 제목 띠·촘촘한 표 | 큰 제목과 여백, 단순 목록 | 작은 업무 제목·일관된 검색 바·강조색·표 헤더 적용 | 참조 기관 로고·이미지는 복사하지 않음 |

## 권장하는 1차 개편 범위

첫 개편은 **현재 제공 기능의 공통 틀과 조회·상세 배치**에 집중한다.

```text
BOOT ERP                         사용자 역할 · 세션 · 로그아웃
업무 관리 / 설정
───────────────────────────────────────────────────────────
업무·과제       │ 현재 메뉴 / 화면 제목
  내/전체 업무  │ 검색 조건                         조회
  과제·비교과   │ 결과 건수                         허용 작업
예산            │ 목록 또는 예산 표
  배정·변경     │────────────────────────────────────────────
지출            │ 선택 상세
  초안·증빙     │ 기본정보 / 첨부 / 이력
설정            │
  기준·계정     │
```

이 틀은 참조에서 확인한 상단·좌측·본문 구분을 현재 기능에 맞춘 적용안이다. 기준 설정은 담당자/관리자 편집과 연구원 확인 완료 기준 조회·책임자 조회를 보존한다. 계정 관리와 추가 본인 확인은 현재 권한 범위로 제한한다.

초기에는 화면 탭을 현재 위치 표시로 사용한다. 참조처럼 여러 폼을 동시에 유지하는 방식은 별도 상태 관리가 필요하므로 바로 복제하지 않는다. 메인 카드도 실제 API와 권한으로 계산할 수 있는 정보부터 도입하고, 미구현 승인 건수나 가상 금액을 실제 현황처럼 넣지 않는다.

## 아직 확인하지 못한 사항

- 예산 상세와 결의서 목록·청구서 내역·첨부 파일 목록은 후속에서 확인했다. 예산변경 전후/차수별 동작은 미확인이다.
- 첨부 업로드/교체/버전/이력 및 결재 처리 이력은 미확인이다.
- 연구원·책임자·담당자 등 다른 역할에서의 메뉴 차이.
- 모바일 지원 및 화면 전환 시 미저장 입력 처리.
- 각 입력의 필수 조건·기관 규칙·저장 후 전이. 관찰만으로 업무 정책을 확정하지 않는다.

현재 분석은 대표 업무 화면의 구조 비교다. 전체 ERP 분석 완료나 기능 동등성을 의미하지 않는다. 후속 검토로 1차 UI 개편의 대표 구조는 확보했으며 변경 전후·버전/처리 이력 등은 해당 기능 설계 시 추가 확인한다.

## 수행과 검증

과제관리·지출관리 이동, 메인 탭 복귀, 화면 스크롤만 수행했다. 읽기 범위를 넓히기 위해 VS Code의 양쪽 사이드바를 접었다. 입력·저장·수정·삭제·상신·승인·파일 다운로드를 수행하지 않았다. 분석 종료 시 참조 메인 화면을 열어두었다.

이번 산출물은 분석 문서와 진행상태 갱신이다. UI 코드·DB·업무 정책 변경은 없으며 애플리케이션 테스트는 재실행하지 않았다. 문서 링크와 공백 검사를 수행했다. 실제 구현 후에는 데스크톱/모바일·키보드·역할별 회귀검수가 필요하다.
