완성 작업 후속: 사용자 추가 요청에 따라 [통합 작업계획](completion-plan.md)과 [작업 프롬프트](completion-prompts.md)를 작성했다. 새 작업은 이 계획의 P0/P1부터 기존 완료 증거를 확인해 이어간다. 아래는 인수인계 작성 당시 기록이며 참조 ERP 대표/상세 분석은 후속 완료, UI 개편·ERP 전체 완성·실자료 입력·Notion 연계는 아직 미수행이다.

후속 갱신: 인수인계 작성 후 사용자가 최종 작업의 main 반영을 요청했다. 작업 브랜치 `6c95e5f`까지 `main`에 반영했으며 현재 기준 브랜치는 `main`이다. 아래 시작 SHA·브랜치·병합 미수행 표기는 인수인계 작성 당시 상태다. [main 반영 기록](history/2026-11-05-main-integration.md)을 우선 참조한다. 이후 추가 병합·배포의 자동 진행을 허용한 것은 아니다.

## 1. 현재 위치와 인수인계 결론

**00~03단계 완료, 04단계는 공통 초안·비공개 첨부·기준 설정만 구현·검수 완료다. 04 전체 완료는 아니며 05~10은 미착수다.**

최근 사용자는 [국립한국교통대학교 산학 ERP](https://sanhak-erp.ut.ac.kr/)의 형태를 참조해 현재 ERP를 구성하고자 중간 점검을 요청했다. 참조 사이트를 VS Code 통합 브라우저로 여는 데 성공했고 사용자가 직접 로그인했다. 마지막으로 확인한 화면은 로그인 후 공지 안내창이다. 이후 사용자가 분석을 중단하고 인수인계 파일 작성을 요청했다.

**다음 작업은 참조 ERP의 실제 업무 화면을 읽기 전용으로 확인하고, 기존 ERP와 메뉴·화면 대응표를 작성하는 것이다.** 상세 분석이나 화면 개편이 이미 끝난 것으로 간주하지 않는다. 이번 작업은 문서 정리이며 앱·DB·업무 정책을 변경하지 않았다.

## 4. 반드시 유지할 확정 정책

- 역할은 연구원·과제책임자·담당자·관리자이며 계정당 하나다. 책임자는 담당 과제·비교과 조회 전용이다.
- 연구원 간 개별 업무·자료는 같은 과제라도 비공개다. 재배정된 동일 업무의 과거 자료는 후임에게 승계하고 원 작성자·이력을 보존한다.
- Google 인증 이메일 기준의 사전 등록 계정만 로그인한다. 이메일 수기 소유 확인, 담당자 우선 일반 계정 관리, 관리자만 관리자 계정 관리 원칙을 유지한다.
- 세션·복구는 [인증 정책](auth-policy.md)의 S-01~S-10을 따른다. 대학 SSO로 전환할 수 있도록 인증 연결과 내부 계정을 분리한다.
- 최종 신청 기능에서는 제출 시 잔액 검사·차감을 같은 트랜잭션으로 처리한다. 승인·지급 시 재차감하지 않는다. 현재 초안 저장과 제출은 구분한다.
- 보완은 차감을 유지한다. 적법한 신청 전 복귀·반려·취소는 복원하고 금액 수정 후 재신청 시 새 잔액을 검사한다.
- 연구원은 담당 과제 전체 항목 간 예산변경을 신청할 수 있으나 과제 간 이동·총액 증감은 불가하다. 총액 증감은 담당자만 수행한다.
- 내부 승인과 대학 ERP 실청구·실제 지급은 별개다. 외부 공식 승인 상태를 별도 필수 절차로 넣지 않는다.
- 금액은 정확한 원 단위로 처리한다. 이력은 덮어쓰거나 삭제하지 않는다. 권한·감사·동시성·중복처리를 서버에서 검사한다.
- 예산 기준은 PDF보다 확정된 Notion 등록 자료를 우선한다. 사업 1차년도(2026학년도), 공통 사용기간 2026-03-01~2026-12-31을 유지한다. 실제 원문·이름·금액은 공개 코드/시험에 복사하지 않는다.
- Notion은 읽기 전용이다. 대학 ERP·Notion·홈페이지 자동 업무 연동과 자동 지급은 구현하지 않는다.

참조 ERP의 메뉴나 안내문을 발견했다고 위 정책을 자동 변경하지 않는다. 최신 사용자 지시·확정 요구·결정기록을 우선한다.

## 6. 참조 ERP 조사 진행상황

| 순서 | 수행·관찰 결과 |
|---|---|
| 일반 웹 도구 조회 | 참조 URL에 접근하지 못함 |
| 외부 브라우저 연결 | 브라우저 접근 호스트 오류. 크롬 UI 접근은 현재 URL 판별 실패로 중단됨. 사용자 로그인 실패로 단정하지 않음 |
| VS Code 내부 브라우저 | 명령 팔레트의 `브라우저: 통합 브라우저 열기` / `Browser: Open Integrated Browser`로 열기 성공 |
| 로그인 전 | 산학 ERP 로그인 화면이 실제 표시됨. 이 내부 브라우저에서는 별도 로그인이 필요했음 |
| 로그인 후 | 사용자가 직접 로그인 완료를 보고했고 `메인화면` 탭의 공지 안내창을 화면으로 확인함 |
| 마지막 상태 | 공지창이 업무 화면을 가리는 상태. 좁은 편집기 영역으로 가로 잘림도 관찰. 공지창 닫기 성공은 확인하지 못함 |
| 미완료 | 전체 메뉴, 역할별 대시보드, 과제/예산 목록·상세, 지출 입력, 첨부/이력 화면, 현재 ERP와의 비교표 |

내부 브라우저 진입은 가능하지만 이후 모든 화면의 조작·접근이 가능한지는 아직 검증하지 않았다. 웹 도구/외부 브라우저 실패를 전체 사이트 장애로 해석하지 않는다. 로그인 후 공지 원문이나 화면의 실제 업무자료를 저장소에 복사하지 않았다. 외부 사이트에 업무 데이터 저장·수정·승인·파일 업로드를 하지 않았다.

## 7. 다음 작업 순서

1. 저장소의 변경사항과 현재 브랜치를 확인하고 보존한다. 이 파일과 STATUS·요구사항·결정기록·04 단계 문서를 먼저 읽는다.
2. 사용자가 열어둔 VS Code 내부 브라우저를 새로 관찰한다. 이전 창 ID·요소 번호·좌표는 재사용하지 않는다. 로그인 화면이면 사용자가 직접 로그인하도록 안내한다.
3. 공지 안내창을 닫고 전체 메뉴와 메인 화면을 읽기 전용으로 확인한다. 확인/닫기와 저장/승인 버튼을 혼동하지 않는다. 열람 외 상태 변경은 하지 않는다.
4. 과제 조회 → 예산 조회 → 지출 목록/상세 순서로 대표 화면을 확인한다. 신규 입력 화면은 레이아웃만 관찰하고 실제 저장·상신·승인은 하지 않는다.
5. 메뉴 위치·분류, 검색조건, 목록 열, 상세 배치, 탭, 버튼, 첨부·이력 표시를 기록한다. 실제 이름·금액 대신 화면 요소와 가상 예시로 정리한다.
6. `참조 화면 / 현재 기능 / 적용 제안 / 보류·차이 / 근거` 대응표를 작성한다. 직접 확인한 사실과 일반적인 UI 제안을 구분한다.
7. 기존 [화면 지도](ui-map.md)를 최신 정책과 대조해 개편안에 반영한다. 이 파일에는 종전 사전신청/사후청구, D-03 미결정 등 과거 초안이 남아 있으므로 그대로 구현 기준으로 사용하지 않는다.
8. 대표 화면 시안과 구체적 변경 범위를 정리한 뒤 현재 구현 기능부터 적용·권한/모바일 회귀검수한다. 참조 분석만으로 보류된 B 정책이나 제출·승인을 활성화하지 않는다.
9. 별도로 04 남은 정책을 확정하면 제출·검토·승인과 03 금액 서비스를 연결하고 W-01/W-02 등 전체 검수를 수행한다. 05 이후·main 병합·운영 배포로 자동 확대하지 않는다.
