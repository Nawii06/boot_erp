# 02단계 — 계정·권한·과제·프로그램

상태: 정책·설계 정리 진행, 기능 구현 미착수 / 목표: 누가 어떤 업무에 접근하는지 서버에서 일관되게 통제한다.

## 선행조건

01단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

2026-10-05에 AC-01~AC-06을 확정했다. Google 로그인(향후 대학 SSO 교체), 이메일 기반 담당자 우선 계정 관리, 역할 1개, 연구원 간 업무 격리, 책임자의 담당 과제·비교과 전체 조회, 재배정 업무 전체 자료 승계가 최신 기준이다. [세션·복구 및 계정 관리 세부 안내](../auth-policy.md)의 S/A 항목은 아직 미결정이다.

## 개발 범위

- Google 로그인·이메일 계정 관리·계정정지, 계정당 1개의 시스템 역할을 구현한다. 인증 제공자와 내부 계정/업무를 분리하여 대학 SSO 교체를 준비한다.
- 사업연차·프로젝트·참여자·사용자 배정을 구현한다. 산공과제와 비교과는 공통 마스터에서 유형으로 구분한다.
- 연구원은 자신의 배정/인수 업무만 조회하고 같은 과제의 다른 연구원 업무도 노출하지 않는다. 책임자는 담당 과제·비교과 전체 자료, 담당자/관리자는 전체 업무를 조회한다.
- 재배정 시 동일 업무의 과거 자료 전체와 연속성을 후임에게 제공하면서 원 작성자·전임자·정정 이력을 보존한다.
- 과제책임자의 모든 쓰기 행위를 차단하고 담당자 업무 설정과 관리자 전산 설정을 분리한다.
- 목록·상세·검색·공통 API·미리보기/다운로드·내보내기용 권한 함수를 공유하도록 준비한다.

## 이 단계의 특이사항

전공·학생명·지도교수 이름이나 클라이언트가 전달한 이메일·프로젝트 ID로 권한을 추정하지 않는다. D-04는 AC-04~AC-06으로 확정했고 D-05는 로그인·계정 담당·단일 역할만 확정했다. 세션/복구·가입 허용·관리자 계정 관리 등의 남은 부분은 답변 후 구현한다. 01의 프로젝트 배정 공통 함수만으로 연구원 간 격리 정책이 완성됐다고 간주하지 않는다.

## 산출물

- 인증·권한 정책·가상 역할별 계정
- 과제·프로그램 목록/상세와 업무 배정 화면
- 서버 권한 통합검수
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-02.md` 갱신

## 완료 기준

- A-01~A-11을 실제 서버 요청으로 검증한다. 세션·계정 운영 미결정은 구현 전에 확정하며, 대학 SSO 전환 구조는 가상 제공자로 검수하고 실제 연결은 기관 사양 확인 후 별도 수행한다.
- 역할별 첫 화면과 빈 목록·배정 해제·정지 계정이 동작한다.
- 동일 브라우저 역할 전환에서 이전 사용자 캐시·데이터가 노출되지 않는다.
- 연결 검수: A-01~A-11. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.

## 이번 단계 제외

과제책임자 승인 기능, 외부 서비스 공유권한 연결.
