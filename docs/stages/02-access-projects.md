# 02단계 — 계정·권한·과제·프로그램

상태: 미착수 / 목표: 누가 어떤 업무에 접근하는지 서버에서 일관되게 통제한다.

## 선행조건

01단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

## 개발 범위

- 계정·로그인·계정정지, 4종 시스템 역할을 구현한다.
- 사업연차·프로젝트·참여자·사용자 배정을 구현한다. 산공과제와 비교과는 공통 마스터에서 유형으로 구분한다.
- 연구원/책임자는 배정 업무, 담당자/관리자는 전체 업무를 조회하도록 만든다.
- 과제책임자의 모든 쓰기 행위를 차단하고 담당자 업무 설정과 관리자 전산 설정을 분리한다.
- 목록·상세·검색·공통 API·미리보기/다운로드·내보내기용 권한 함수를 공유하도록 준비한다.

## 이 단계의 특이사항

전공·학생명·지도교수 이름으로 권한을 추정하지 않는다. 클라이언트가 전달한 프로젝트 ID를 신뢰하지 않는다. D-04/D-05가 결정되어야 상세 증빙·계정 발급 범위를 확정할 수 있다.

## 산출물

- 인증·권한 정책·가상 역할별 계정
- 과제·프로그램 목록/상세와 업무 배정 화면
- 서버 권한 통합검수
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-02.md` 갱신

## 완료 기준

- A-01~A-05를 실제 서버 요청으로 검증한다.
- 역할별 첫 화면과 빈 목록·배정 해제·정지 계정이 동작한다.
- 동일 브라우저 역할 전환에서 이전 사용자 캐시·데이터가 노출되지 않는다.
- 연결 검수: A-01~A-05. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.

## 이번 단계 제외

과제책임자 승인 기능, 외부 서비스 공유권한 연결.

## 되돌림·보존

배정·역할 변경이력으로 복원하고 계정 삭제로 과거 작성자가 사라지지 않게 한다.
