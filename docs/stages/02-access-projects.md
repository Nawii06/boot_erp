상태: 진입 정책 확정, 기능 구현 미착수 / 목표: 누가 어떤 업무에 접근하는지 서버에서 일관되게 통제한다.

## 선행조건

01단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

2026-10-05에 AC-01~AC-06 및 AC-08~AC-11을 확정했다. Google 로그인(향후 대학 SSO 교체), 이메일 기반 담당자 우선 계정 관리, 역할 1개, 연구원 간 업무 격리, 책임자의 담당 과제·비교과 전체 조회, 재배정 업무 전체 자료 승계가 최신 기준이다. [세션·복구 및 계정 운영 정책](../auth-policy.md)의 S/A 항목도 확정됐으며 이전 미결정 안내를 대체한다.

## 개발 범위

- Google 로그인·이메일 계정 관리·계정정지, 계정당 1개의 시스템 역할을 구현한다. 인증 제공자와 내부 계정/업무를 분리하여 대학 SSO 교체를 준비한다.
- 사전 등록 이메일만 로그인하게 하고, 다른 이메일로 만든 Google 계정의 소유를 담당자가 수기 확인한 기록과 상태를 관리한다. 관리자 계정 관리·관리자 역할 부여/회수는 관리자만 가능하며 세션·복구는 확정 S-01~S-10을 적용한다.
- 사업연차·프로젝트·참여자·사용자 배정을 구현한다. 산공과제와 비교과는 공통 마스터에서 유형으로 구분한다.
- 연구원은 자신의 배정/인수 업무만 조회하고 같은 과제의 다른 연구원 업무도 노출하지 않는다. 책임자는 담당 과제·비교과 전체 자료, 담당자/관리자는 전체 업무를 조회한다.
- 재배정 시 동일 업무의 과거 자료 전체와 연속성을 후임에게 제공하면서 원 작성자·전임자·정정 이력을 보존한다.
- 과제책임자의 모든 업무 쓰기를 차단하고 담당자 업무 설정과 관리자 전산 설정을 분리한다. 본인 로그아웃 등 세션 보안 행위는 업무 쓰기와 구분한다.
- 목록·상세·검색·공통 API·미리보기/다운로드·내보내기용 권한 함수를 공유하도록 준비한다.

## 이 단계의 특이사항

전공·학생명·지도교수 이름이나 클라이언트가 전달한 이메일·프로젝트 ID로 권한을 추정하지 않는다. D-04/D-05의 진입 정책은 확정됐다. 수기 확인은 Google 토큰 검증을 대체하지 않으며 미등록 또는 확인 대기/실패 계정에는 세션을 발급하지 않는다. OAuth 실행 설정과 추가 본인 확인 수단은 구현 시 검증한다. 01의 프로젝트 배정 공통 함수만으로 연구원 간 격리 정책이 완성됐다고 간주하지 않는다.

## 완료 기준

- A-01~A-12를 실제 서버 요청으로 검증한다. 확정된 세션·계정 운영 기준을 적용하며, 대학 SSO 전환 구조는 가상 제공자로 검수하고 실제 연결은 기관 사양 확인 후 별도 수행한다.
- 역할별 첫 화면과 빈 목록·배정 해제·정지 계정이 동작한다.
- 동일 브라우저 역할 전환에서 이전 사용자 캐시·데이터가 노출되지 않는다.
- 연결 검수: A-01~A-12. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 02에서 만드는 권한 경계와 대표 서버 경로를 가상 자료로 검수한다. 04 이후 구현할 실제 증빙·청구·지급·보고서 경로의 권한도 각 단계에서 재검수하며, 02 검수로 미구현 업무 전체의 통과를 선언하지 않는다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.
