# 01단계 — 개발 기반·DB·실행 환경

상태: 완료 (2026-10-05, 로컬 개발 기반 범위) / 목표: 새로운 개발자가 같은 명령으로 실행·검수할 수 있는 기반을 만든다.

## 이번 수행 결과

최소 Next.js 앱, 8개 기반 테이블과 SQL 마이그레이션, Drizzle 정의, 비활성 가상 seed, 인증 차단 경계, 서버 권한 검사, bigint 금액, 멱등 명령·트랜잭션·감사기록을 구현했다. 잠금파일 재설치, 타입·단위검사 4건, 실제 DB 하위 검수 9건, 개발/프로덕션 HTTP 검수와 Edge 화면 확인을 수행했다. 신규 빈 개발·시험 DB에 적용하고 가상자료가 있는 DB에서 재실행도 확인했다.

실행·스키마 범위: [01 인수인계](../foundation.md). 명령·실패·한계·원격 결과: [01 작업기록](../history/2026-10-05-phase-01.md). 실제 로그인, 예약·지급 업무 검수, 파일 기능·운영 배포는 미수행이다. 02는 자동 시작하지 않았으며 D-04/D-05 확인이 선행되어야 한다.

## 선행조건

수행 후 [체크리스트 재점검](../history/2026-10-05-phase-01-review.md)에서 완료 증거·추가 재현 범위·D-04/D-05 및 후속 업무 검수의 미완료 사항을 구분했다. 현재 PC의 01 로컬 기반 완료 상태는 유지하며 다른 PC 전체 설치·실제 업무 인수 완료를 뜻하지 않는다.

00단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

## 개발 범위

- 확정된 기술만 사용하여 최소 웹 앱·설정·의존성 잠금파일을 구성한다.
- 업무 모듈 경계와 DB 마이그레이션 방식을 정하고 논리 모델을 물리 구조로 옮긴다.
- 로그인 연결 지점·서버 권한 정책 인터페이스·정확한 금액 타입·트랜잭션 서비스·감사기록 기반을 만든다.
- 가상 데이터 생성, 환경변수 예제, DB 및 파일 저장소 분리, 공통 오류·입력검증 방식을 준비한다.
- 실제로 실행된 설치·실행·빌드·테스트 명령을 README에 기록한다. 개발·시험 DB를 운영과 분리한다.

## 이 단계의 특이사항

개발용 로그인 우회나 고정 관리자 계정을 운영 기본값으로 남기지 않는다. 파일 업로드·공개 접근은 이후 권한 구현 전 활성화하지 않는다. 마이그레이션은 빈 DB와 기존 개발 DB 양쪽에서 검증한다.

## 산출물

- 선택 기술의 앱 디렉터리·패키지/잠금파일·환경변수 예제
- DB 스키마·마이그레이션·가상 seed
- README의 실제 실행·테스트 명령과 개발 구조 설명
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-01.md` 갱신

## 완료 기준

- 깨끗한 개발환경에서 의존성 설치·DB 생성·앱 시작이 재현된다.
- 비밀정보가 브라우저 번들·저장소에 포함되지 않는다.
- 금액의 정확한 타입, 참조키와 트랜잭션 기본 동작을 확인한다.
- 연결 검수: 기반 실행·DB 검사, O-03. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.

## 이번 단계 제외

전 메뉴 구현, 실운영 로그인·배포, 외부 연동.

## 되돌림·보존

개발 DB에만 마이그레이션을 적용하고 실패 시 복원/재생성한다. 운영 DB에 같은 초기화 명령을 실행하지 않는다.
