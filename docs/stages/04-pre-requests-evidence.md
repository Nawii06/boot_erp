# 04단계 — 사전 사용신청·증빙 기반

상태: 미착수 / 목표: 연구원이 사용계획을 신청하고 담당자가 필요한 절차와 서류를 확인하게 한다.

## 선행조건

03단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

## 개발 범위

- 지출 유형·필수 입력항목·조건부 증빙 설정을 담당자 업무 설정으로 만든다.
- 집행 건 생성, 사전신청 임시저장·제출·보완·검토를 구현한다.
- 공식 사전품의 문서번호·상태·확인자·근거파일을 내부 검토와 분리한다.
- 검토 완료에 따른 예산 예약과 상태 변경을 원자적으로 연결한다.
- 비공개 파일 저장·접근 검사·서류별 제출/검토 상태·파일 교체이력을 구현한다.

## 이 단계의 특이사항

Notion 양식의 단가·3일 전 안내 등을 현재 공식 규칙으로 자동 확정하지 않는다. D-06/D-07의 근거·시행일이 있는 기준만 사용한다. ZIP이 있다는 이유로 필수서류 전체 제출을 체크하지 않는다.

## 산출물

- 사전신청·보완·공식 사전품의 기록 화면
- 유형별 입력/증빙 설정과 비공개 파일 모듈
- 예약 연결·파일 권한 검수
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-04.md` 갱신

## 완료 기준

- W-01/W-02와 F-01~F-03을 확인한다.
- 연구원은 배정 업무의 허용 예산항목만 선택한다.
- 검토 단계에서 예산 초과가 나면 상태와 예약 모두 변경되지 않는다.
- 연결 검수: W-01, W-02, F-01~F-03. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.

## 이번 단계 제외

공식 전자결재 자동 상신, Notion 양식 자동 수정.

## 되돌림·보존

제출본과 파일 버전을 보존하고 철회/보완으로 처리한다. 임시 파일 정리만으로 확정 증빙을 삭제하지 않는다.
