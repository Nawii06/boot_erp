# 10단계 — 운영 배포·백업복구·인수인계

상태: 미착수 / 목표: 승인된 환경에서 지속 운영·복구·인수인계가 가능한 상태로 전환한다.

## 선행조건

09단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

## 개발 범위

- 운영 서버·접속범위·HTTPS·인증·계정복구·비밀정보 주입을 설정한다.
- 운영 마이그레이션, 파일 저장소, 로그 마스킹, 장애 확인·알림 경로를 구성한다.
- DB와 증빙을 함께 백업하고 별도 환경에 실제 복원하여 대조한다.
- 배포 전후 확인과 실패 시 롤백 절차를 실행 가능한 명령으로 문서화한다.
- 역할별 사용 안내, 관리자 운영 안내, 정기점검·업데이트·지원 절차를 인수인계한다.

## 이 단계의 특이사항

고정 IP가 있다는 이유만으로 운영 준비 완료가 아니다. 08~09 검수와 복구 확인을 거치고, 사용자가 승인한 운영 범위에서 배포한다. 공개 저장소에 서버 비밀정보·접속키를 넣지 않는다.

## 산출물

- 실제 배포환경용 설정·비밀정보 없는 예제
- docs/operations-runbook.md, docs/user-guide.md
- 복구 시험 결과·배포/인수인계 기록
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-10.md` 갱신

## 완료 기준

- O-01~O-03을 검증하고 실제 RPO/RTO 측정 결과를 목표와 비교한다.
- 운영에서 개발 시드·테스트 인증·공개 업로드 경로가 비활성화되어 있다.
- 담당자·관리자가 각각 업무 처리와 복구 절차를 확인한다.
- 연결 검수: O-01~O-03. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.

## 이번 단계 제외

미승인 외부 연동·웹사이트 공개·자동 송금.

## 되돌림·보존

검증된 DB·파일 백업과 앱 버전으로 복구한다. 스키마 변경 후 코드만 되돌려 불일치를 만들지 않는다.
