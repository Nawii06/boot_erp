# 06단계 — 대학 ERP 실청구·지급·정산

2026-11-05 정정: 최신 BC/EX 정책의 단일 신청·신청 즉시 차감·승인/지급 시 재차감 금지를 반영했다. 최신 실행 순서는 [완성 계획](../completion-plan.md)과 [단계별 작업 프롬프트](../completion-prompts.md)를 함께 따른다. 이번 변경은 문서 정정이며 기능 구현은 미수행이다.

상태: 2026-11-06 P5 구현·DB10건/가상 지급→환입·마감 UI 검수 통과, 실환경 인수 별도 / 목표: 담당자의 실제 대학 ERP 처리와 지급 결과를 추적 가능하게 기록한다.

WF-01~04 적용: 신청 한 건/외부 문서 한 건, 재상신 이력 추가, 부분 지급과 총액=공제+실수령, 원지급별 환입 한도, 동일 연차/기간의 명시적 예산복원, 마감/사유 있는 재개방을 구현했다. 지급일/환입일은 별도 실적 기준이며 자동 상신·자동 지급은 없다. [사용 안내](../user-guide.md), [진행표](../execution-progress.md).

## 선행조건

05단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`의 최신 BC/EX 결정과 이 단계의 미결정을 구분하고 이전 단계의 중대 결함을 먼저 해결한다.

D-08의 실청구 묶음·부분 지급·배분 범위와 D-09의 환입 실제 확인·연차별 예산복원·지급 후 취소/정정·마감/재개방 조건을 해당 기능 전에 확정한다. 정책 미확정을 임의 허용으로 해석하지 않는다. 외부 공식 승인 상태를 본 ERP의 별도 필수 단계로 추가하지 않는 기존 결정은 유지한다.

## 개발 범위

- 실청구 대기 목록과 문서번호·상신일·처리자·청구 배분을 구현한다.
- 반려·재상신·취소를 시도별로 보존하고 대학 ERP 처리완료와 지급완료를 구분한다.
- 확정된 부분 지급·지급배분 범위에서 실제 지급 확인 근거와 이력을 기록하고 중복처리를 방지한다. 지급 기록은 원 신청의 유효 차감을 다시 적용하거나 단순 감소시키지 않는다.
- 환입·정정·취소와 예산복원 여부를 분리하고 원거래를 연결한다.
- 증빙·지급 미결정 확인 후 정산 마감, 사유 있는 재개방을 구현한다.

## 이 단계의 특이사항

본 ERP는 실제 송금·대학 ERP 로그인 자동화를 수행하지 않는다. 지급등록은 실제 결과의 기록이며 내부 승인·실청구·실제 지급은 각각 구분한다. 신청 시 이미 발생한 가용예산 차감을 승인·실청구·지급으로 다시 적용하지 않는다. 미지급과 지급액의 구성 표시가 바뀌더라도 같은 신청의 유효 차감 총액과 가용액이 자동으로 바뀌어서는 안 된다. 공제·원천징수가 있으면 예산 집행 총액과 실수령액을 구분하고 세액을 임의 계산하지 않는다.

## 완료 기준

- E-01~E-07과 B-06을 검증한다.
- 중복 지급 확인 요청, 확정액 초과, 원거래 초과 환입을 검사한다.
- 지급 사건·배분·감사 기록을 원자적으로 저장하고 일부만 반영되는 상태를 차단한다. 지급 기록 시 신청 차감 총액과 가용액이 재차감되거나 단순 복원되지 않음을 검증한다.
- 유효 차감 90만원 신청에 40만원/50만원 부분 지급을 기록하는 정책이 확정된 경우, 지급 합계만 90만원으로 증가하고 신청 차감 총액은 90만원을 유지한다.
- 실제 환입 확인과 확정된 복원정책을 충족한 경우에만 복원 사건을 남긴다. 정책 미확정·지급 미확인 상태를 성공 검수로 기록하지 않는다.
- 연결 검수: E-01~E-07, B-06. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.

실제 지급 실행, 외부 ERP API 연동, 세무 자동판정.

원거래 삭제 대신 확인된 취소·환입·정정 사건을 남긴다. 지급 발생 건은 일반 신청 취소 경로로 복원하지 않는다. D-09 복원정책이 불명확한 건은 예산복원을 보류하고 원거래·미확인 상태를 보존한다.
