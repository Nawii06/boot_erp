# 06단계 — 대학 ERP 실청구·지급·정산

상태: 미착수 / 목표: 담당자의 실제 대학 ERP 처리와 지급 결과를 추적 가능하게 기록한다.

## 선행조건

05단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

## 개발 범위

- 실청구 대기 목록과 문서번호·상신일·처리자·청구 배분을 구현한다.
- 반려·재상신·취소를 시도별로 보존하고 대학 ERP 처리완료와 지급완료를 구분한다.
- 부분 지급, 지급 확인 근거, 지급배분, 예약 전환과 중복처리 방지를 구현한다.
- 환입·정정·취소와 예산복원 여부를 분리하고 원거래를 연결한다.
- 증빙·지급 미결정 확인 후 정산 마감, 사유 있는 재개방을 구현한다.

## 이 단계의 특이사항

본 ERP는 실제 송금·대학 ERP 로그인 자동화를 수행하지 않는다. 지급등록은 실제 결과의 기록이다. 공제·원천징수가 있으면 예산 집행 총액과 실수령액을 혼동하지 않으며 세액을 임의 계산하지 않는다.

## 산출물

- 실청구·상신이력·지급·환입·마감 화면
- 문서/청구 연결·지급배분·정정이력
- 금액 전 과정 검수
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-06.md` 갱신

## 완료 기준

- E-01~E-07과 B-06을 검증한다.
- 중복 지급 확인 요청, 확정액 초과, 원거래 초과 환입을 검사한다.
- 지급확인과 예약 감소 중 하나만 성공하는 상태가 없다.
- 연결 검수: E-01~E-07, B-06. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.

## 이번 단계 제외

실제 지급 실행, 외부 ERP API 연동, 세무 자동판정.

## 되돌림·보존

원거래 삭제 대신 확인된 취소·환입·정정 사건을 남긴다. 복원정책 불명확 건은 예산복원을 보류한다.
