# 03단계 — 예산배정·예산변경·금액 서비스

상태: 2026-10-18 구현·검수 완료. [검수 기록](../history/2026-10-18-phase-03.md), [사용 안내](../phase-03-guide.md). 실자료 DB 이관·후속 신청 화면·지급 구현은 제외한다. 목표: 프로젝트와 항목별 예산을 정확하게 계산하고 변경 근거를 추적한다.

## 선행조건

02단계 완료 증거와 `../STATUS.md`를 확인한다. `../07-decisions.md`에서 이 단계에 필요한 정책이 결정되었는지 확인한다. 이전 단계의 미해결 중대 결함이 있으면 관련 구현을 먼저 해결한다.

## 개발 범위

준비 결과: [신청 전이·배정자료 대조](../history/2026-10-18-phase-03-readiness.md). Notion 원본을 변경하지 않고 프로젝트·배정 구조를 확인했다. 후속 [기준 확정](../history/2026-10-18-phase-03-baseline.md)으로 Notion 우선·공통 기간·등록 기준 분류를 확정했다. 준비 질문을 반복하지 않고 가상 자료로 기능 구현·검수를 진행할 수 있다. 실자료 DB 반영은 별도 수행한다.

- 재원·연차·분류코드·내부 예산항목, 최초예산·현재예산을 관리한다.
- 변경신청 표지와 여러 변경행을 구현하고 예산항목 ID를 직접 연결한다.
- 항목 간 조정/총액 증감 구분, 변경전 버전 확인, 근거와 처리이력 보존을 구현한다.
- 신청 즉시 차감·신청 전 복귀 시 복원 공통 서비스를 만들고 예산확정과 감사이력을 원자적으로 반영한다. 사전 예산·사후 청구를 분리하지 않는다.
- [확정 예산 정책](../budget-policy.md)의 D-02/D-03과 비목·세목·세세목 내부 코드를 적용한다. 연구원 담당 과제 전체 항목 간 변경, 담당자 총액 증감, 담당자·관리자 확정 대행, 필수 비공개 첨부와 권한 검수를 포함한다.

## 이 단계의 특이사항

현재예산에 이미 반영된 변경을 다시 더하지 않는다. 신청 시 차감한 금액은 승인·지급 때 다시 차감하지 않는다. 예산부족 검증과 예약 기록은 같은 트랜잭션으로 보호해야 한다.

## 산출물

- 예산 목록·세부항목·변경신청·확정 화면
- 금액 계산·예약·해제 서비스와 DB 제약
- 예산변경·동시성 검수 결과
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-03.md` 갱신

## 완료 기준

아래 기준은 03 범위에서 통과했다. 단위 8건, DB/HTTP 핸들러 41건(부모 포함), 타입·빌드·실제 브라우저·문서 검수 결과는 [작업기록](../history/2026-10-18-phase-03.md)을 따른다. B-10/B-11/W-05의 전체 지출 화면은 후속 단계에서 검수한다.

- B-01~B-05 및 B-07~B-09를 검증한다. 동시 예약은 병렬 요청으로 확인한다.
- 변경이 중간 실패하면 모든 변경행이 함께 취소된다.
- 확정·재시도·취소·낡은 버전 충돌의 합계가 예상과 일치한다.
- 연결 검수: B-01~B-05 및 B-07~B-09. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.
- B-10/B-11 및 W-05의 공통 금액 서비스 검수로 처리 시작·회수 경합, 보완 중 차감 유지, 승인 후 취소 권한을 확인한다. 전체 신청 화면 검수는 04/05에서 이어간다.

## 이번 단계 제외

규정 근거 없는 단가 고정, 실제 예산자료 자동 이관.

## 되돌림·보존

확정 전 초안은 수정 가능, 확정 이후는 취소/정정 사건으로 남긴다. 원장 직접 덮어쓰기로 맞추지 않는다.
