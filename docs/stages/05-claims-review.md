# 05단계 — 동일 신청의 상세 내역·검토·보완

2026-11-05 정정: [확정 예산 정책](../budget-policy.md)의 BC-01~BC-13과 EX-01~EX-12에 맞춰 종전 사전신청/사후청구 분리 표현을 정리했다. 최신 실행 순서는 [완성 계획](../completion-plan.md)과 [단계별 작업 프롬프트](../completion-prompts.md)를 함께 따른다. 이번 변경은 문서 정정이며 기능 구현은 미수행이다.


상태: 2026-11-06 P4 구현·격리 DB/가상 UI 왕복 검수 통과, 실환경 인수 별도 / 목표: 동일 지출 신청의 상세 내역·서류별 보완·제출본·정정 이력을 연결한다. 별도 사후 신청을 생성하여 다시 차감하지 않는다.

## 선행조건

04/P3의 제출·차감·승인 검수 증거와 `../STATUS.md`를 확인한다. EX-13~15/WF-01 확정으로 동일 신청의 상세·서류별 의견·보완·정정을 구현했다. 단일 신청·단일 예산항목, 복수 산출행, 금액 변경은 복귀/복원 후 재신청을 적용한다. 운영/인수 미충족은 [진행표](../execution-progress.md)에 따로 남긴다.

D-08의 추가/분할 신청·세부행·실청구 묶음 및 대행 범위는 해당 기능을 구현하기 전에 확정한다. EX-02의 신청 한 건당 예산항목 1개와 본인 배정 업무·같은 과제 범위는 이미 확정됐으므로 다시 미결정으로 돌리지 않는다. B-01~B-09의 세부 기준과 실제 단가·한도·기한 등은 최신 EX 결정 및 사용자 후속 답변을 따른다.

## 개발 범위

- 동일 신청에 공통 정보·허용된 상세 내역·증빙·사용일 및 제출본 버전을 연결한다. 유형별 필드와 필수서류는 확정된 기준만 적용한다.
- 담당자의 서류별 보완과 의견, 연구원의 보완 제출, 이전 제출본·첨부·처리 이력을 보존한다. 보완 중에는 신청 효력과 차감을 유지한다.
- 금액 변경은 적법한 신청 전 복귀 → 기존 차감 1회 복원 → 수정 → 현재 가용액 검사 → 재신청·새 금액 차감으로 처리한다. 검토 중 확정금액만 덮어써 잔액을 바꾸지 않는다.
- 추가/분할 신청·묶음이 확정되면 해당 범위만 구현하고 동일 신청·승인·지급에 따른 중복 차감을 방지한다.
- 확정된 대행 범위 안에서 실제 행위자·업무 주체·사유를 남긴다. 재배정 시 원 작성자·이력을 보존하고 후임은 인수한 동일 업무 자료만 승계한다.

## 이 단계의 특이사항

신청금액·내부 승인·대학 ERP 실청구·실제 지급은 별도 사실이다. 같은 신청을 보완하거나 승인·지급한다고 다시 차감하지 않는다. 금액 변경에는 복귀·복원·잔액 재검사 이력을 남기며 제출본을 덮어쓰지 않는다. 내부 승인에 외부 공식 승인 상태를 필수 단계로 추가하지 않는다.

## 산출물

- 청구 작성·검토대기·보완·확정 화면
- 제출본·검토의견·복귀/복원·재신청·금액 정정 기록
- 연구원/담당자 왕복 업무 검수
- 공통: `docs/STATUS.md`, `CHANGELOG.md`, `docs/history/YYYY-MM-DD-phase-05.md` 갱신

## 완료 기준

- W-03~W-05, F-03 및 관련 권한 검수를 수행한다.
- 확정 후 연구원의 직접 수정과 권한 밖 첨부 교체를 차단한다.
- 확정된 범위에서 상세 내역 합계와 신청금액을 대조하고 동일 금액 보완·승인 시 차감액이 변하지 않음을 확인한다.
- 100만원 신청을 적법하게 복귀한 뒤 90만원으로 재신청하면 100만원 복원 후 90만원만 차감한다. 보완 중 직접 금액 수정·이중 복원·중복 요청을 차단한다.
- 추가/분할 신청 정책이 미확정이면 관련 기능을 활성화하지 않고 해당 검수를 미실행으로 기록한다.
- 연결 검수: W-03~W-05, F-03. [전체 검수표](../06-acceptance.md)에 실제 결과를 연결한다.
- 실패·미실행·미결정을 기록하고 다음 단계 진입 가능 여부를 보고한다.
